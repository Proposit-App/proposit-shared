# `@proposit/shared@0.5.1` — Server-discovered fixes

**Date:** 2026-05-07
**Status:** Awaiting commit + publish (fixes already in shared's working tree, uncommitted)
**Source:** `proposit-server` adoption of `@proposit/shared@0.5.0` during the source-as-claim wave-1 PR

## Summary

While bringing `proposit-server` onto `@proposit/shared@0.5.0`, four schema-level bugs in the published `0.5.0` artifact surfaced. The server implementer worked around them by directly patching the installed `node_modules/@proposit/shared/dist/` files — those patches cannot survive `pnpm install` and cannot deploy through Vercel/CI. The server PR is therefore blocked on a `0.5.1` release that lands the corresponding source fixes.

The fixes are **already in shared's working tree** (uncommitted modifications to four files). This change request requests committing them, bumping to `0.5.1`, publishing, and tagging — no new code work needed.

### Fix 1: `ClaimSchema.citation` must be `Nullable`

**File:** `src/schemas/model/claims.ts:59`

**Bug:** Field declared `Type.Optional(IEEEReferenceSchema)`. Optional but not nullable — accepts `undefined`/absent, rejects `null`.

**Server symptom:** Postgres stores `citation: NULL` for normal-type claims (no IEEE reference). When the server returns a normal-claim payload, TypeBox parsing fails with a validation error on the `null` value.

**Fix (already in working tree):** `Type.Optional(Nullable(IEEEReferenceSchema))`.

**Verification suggestion:** add a unit test that round-trips a `TClaim` with `type: "normal", citation: null` and asserts no validation error.

### Fix 2: `ClaimCitationSchema` should not redeclare `version`

**File:** `src/schemas/model/citations.ts:9`

**Bug:** Schema declared:

```ts
Type.Intersect([
    CoreClaimCitationSchema,
    Type.Object({
        argumentId: UUID,
        version: Type.Number(),
        createdOn: EncodableDate,
    }),
])
```

The `version` field is wrong here. Citation edges don't have a single `version` — they have `citingClaimVersion` and `sourceClaimVersion` (both inherited from `CoreClaimCitationSchema`). The standalone `version: Type.Number()` was leftover from `claimSources` and shouldn't be re-added on the shared-side intersect.

**Server symptom:** Server's renamed `claimCitations` table has `citingClaimVersion` and `sourceClaimVersion` (no top-level `version` column). Schema validation fails because the wire payload doesn't carry a `version` the schema demands.

**Fix (already in working tree):** drop the `version: Type.Number()` line. The diff is exactly:

```diff
-        version: Type.Number(),
```

**Verification suggestion:** add a unit test that parses a `TClaimCitation` with `citingClaimVersion: 1, sourceClaimVersion: 1` and no top-level `version` field, asserting success.

### Fix 3: `ArgumentEngineSnapshotSchema` premise `role` must be optional

**File:** `src/schemas/snapshot.ts` (around line 64)

**Bug:** Per-premise data inside the engine snapshot's `premises` array required a `role: Type.Union([Type.Literal("conclusion"), Type.Literal("supporting")])` field.

**Why it's wrong:** `proposit-core@0.11.0` no longer embeds per-premise `role` in the engine snapshot. The conclusion role is tracked at the snapshot root via `conclusionPremiseId`; individual premises don't carry their role in the snapshot wire format. Required `role` rejects valid v0.11 snapshots.

**Server symptom:** Any code path that calls `ArgumentEngine.fromSnapshot()` and then re-serializes the snapshot (e.g., the server's `engineCache` round-trip or any wire-format consumer) fails validation on premises that don't have an explicit `role`.

**Fix (already in working tree):** `role` field marked optional in both the omit list and the override layer of the `OptionalChecksumPremise` intersect. Diff already in the working tree adds:

```ts
"role",  // in the omit array
// and:
role: Type.Optional(
    Type.Union([
        Type.Literal("conclusion"),
        Type.Literal("supporting"),
    ])
),
```

**Verification suggestion:** add a unit test that parses an `ArgumentEngineSnapshot` with premises that omit `role`, asserting success.

### Fix 4: `CHECKSUM_CONFIG.premiseFields` should fall back to default

**File:** `src/checksum.ts`

**Bug:** Shared declared `premiseFields: new Set(["argumentId", "argumentVersion", "role", "createdOn", "creatorId", "title"])`. This 6-field hash mismatches `proposit-core@0.11.0`'s 4-field internal `PremiseEngine` checksum (which only hashes `argumentId`, `argumentVersion`, `type`, `derivedClaimId` and strips extra fields before hashing).

**Server symptom:** Server-side checksum computations diverged from client/engine-side checksums. Premise rows persisted by the server failed the engine's `checkValidity` step because the stored checksum and the engine-recomputed checksum didn't match.

**Fix (already in working tree):** drop the explicit `premiseFields` override; let `createChecksumConfig` fall back to `DEFAULT_CHECKSUM_CONFIG.premiseFields` which matches core's 4-field hash. The working-tree diff replaces the field set with an explanatory comment.

**Verification suggestion:** add a checksum regression test that asserts `CHECKSUM_CONFIG.premiseFields` equals `DEFAULT_CHECKSUM_CONFIG.premiseFields` (or is omitted).

## Why patch versus minor

These are all bug fixes against an already-published API surface — nothing new being added. Patch bump (`0.5.0 → 0.5.1`) is correct semantics. The combined change is small (~30 lines of diff plus tests) and the version-policy preference in shared's CLAUDE.md is to use `patch` for most changes.
