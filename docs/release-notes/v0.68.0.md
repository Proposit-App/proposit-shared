# Release notes — upcoming

## The mobile app can reach three things it could only see

Three routes the web app had always called directly now have client methods, so
any consumer can reach them rather than only the app that happens to run in the
same process as the server.

A caller can list the arguments waiting to be claimed by their author, and read
one of them. The claim action itself already existed — a client could take
ownership of a claimable argument but had no way to find one, which is a strange
shape to ship and the reason nothing consumed it.

A caller can resolve a username to its public profile. And a caller can read and
write the accept/reject decisions readers make on a premise while reading, in bulk
for a whole argument rather than one premise at a time, with the request and
response shapes now described in the library instead of privately inside the web
app's route folder. Two apps disagreeing about what a decision means was the risk
there; now there is one contract.

## The rules for authoring against a source text live in one place

Deciding whether an attribution may still be edited, whether an expression may be
marked unspoken, and converting a text selection into the code-point offsets the
origin format stores — these were written down in the web app, and then written
down again in the mobile app when it grew the same surface.

They are the same decisions either way and they now come from the library, at
`@proposit/shared/engine/origin-authoring`. The reading-side counterparts were
already shared; this is the half that had been left behind. Both apps drop their
local copies next.

A rule written down twice is the recurring way this codebase has produced bugs:
the two copies drift, and nothing checks them against each other. There were three
answers to "may this attribution still be edited?" before this change.
