# v0.15.2 release notes

This release fixes a response-validation bug in the entire-argument
response schema: `GET /api/v1/argument/[id]/[v]/entire` returned a 500
for every v2-ingested argument that carried a url-only citation claim.
Backward-compatible schema widening — no peer-dep changes, no breaking
change to existing schemas.

## What changed

- **`CitationClaimSchema`** (`@proposit/shared/schemas/model/claims`,
  re-exported via the `claims`/`model` surface and embedded in
  `FullArgumentSchema` as `claims: Type.Array(ClaimSchema)`) — the
  `citation` field is now nullable: `Nullable(IEEEReferenceSchema)`
  instead of the previous non-null `IEEEReferenceSchema`.

## Why

v2 ingestion legitimately produces **url-only citation claims** — a
`url` is present, but no structured IEEE reference was extracted, so the
read path returns `citation: null`. The pre-0.15.2 schema required a
non-null structured IEEE object, so every such claim failed response
validation. Because all three branches of the `ClaimSchema` union then
failed, TypeBox reported the error against the first branch
(`claims/N/kind must be equal to constant`), masking the real failing
field (`citation: null`).

The fix is a **widening, not a replacement**: full structured IEEE
citations remain valid; url-only citations (null citation) are now also
valid. The `url` string is what distinguishes a citation claim from the
normal and axiomatic branches, so a null `citation` does not collide with
the other branches of the union.

## Peer-dep range

No peer-dep changes. `IEEEReferenceSchema` is unchanged; only its
nullability inside `CitationClaimSchema` widened.

## Consumer migration

None required for type safety — `TCitationClaim["citation"]` widens from
`TIEEEReference` to `TIEEEReference | null`, so any consumer that already
handled the read-coerced row shape (where `citation` could be null) now
type-checks correctly. `proposit-server` flips its `@proposit/shared` dep
to `^0.15.2` to clear the entire-argument 500. `proposit-mobile` is not a
direct consumer of this surface today, but the tarball-validation gate
still applies before publish.

## Versioning

Pre-1.0 patch bump (`0.15.1` → `0.15.2`) — backward-compatible widening
of an existing schema field, no breaking change.
