# Release notes — upcoming

## The review no longer tells you a False conclusion "holds"

When a conclusion came out False, Unknown or Contested and you had answered any
claim it draws on, the results line read **"Conclusion: False. You assigned
this. It holds only because you assigned it."** Both of those last sentences are
about a value that holds, and none of those three values does. They now appear
only beside a True conclusion.

The same mistake reached the argument line, which could say **"Doesn't reach its
conclusion — the conclusion came from you"** beside a conclusion rendered False,
under an explanation that opens by saying the conclusion holds. That reason is
now given only when the conclusion actually comes out true.

## A collision in the argument's own conclusion is caught

The review invites you to accept or reject the step inside the conclusion itself
whenever there is one. If accepting it collided with values you had already
given, nothing noticed: no alert, no explanation of what collided, no way out
offered — and the review could be finished. The identical collision one premise
further down has always stopped the review. It now stops it wherever it happens,
with the same alert and the same ways out.

Some collisions leave every summary reading clean — a conclusion that comes out
true, no premises rejected, nothing unsatisfiable — while a claim underneath is
still held both ways. Those are surfaced too, rather than being inferred from
summaries that cannot see them.

## Reloading the page no longer walks you past the gate

A review stopped by a collision is held until you resolve it. Reloading the page
and stepping forward used to release it, because nothing had re-checked the
review in the new session and "not checked" was read as "nothing wrong". It is
now read as what it is, and the review stays held until a fresh check clears it.
Starting a new review no longer inherits the previous one's block either.

## Your review survives a bad read

Two ways a saved review could be thrown away have been closed. A stored result
this version cannot read no longer takes your answers with it — the answers are
kept and only the recomputable part is dropped. And a review that read back
perfectly is no longer deleted when the browser refuses the follow-up write, as
it does when storage is full or in private browsing.

## Two explanations corrected

The worked example for "its premises hold and its conclusion doesn't follow"
drew an accepted step between a true premise and a false conclusion — which is
now the Contested collision, not that outcome at all, and the example was
teaching readers to recognise the wrong thing. Its definition also described the
finding as a verdict on whether the conclusion follows in general; it is a gap
under the values you supplied, and the separate validity check is what answers
the stronger question. Both fixed.
