# v0.17.0 release notes

## Pipeline stage lifecycle — status rename + new states

`PipelineStageSchema.outcome` is renamed to **`status`** and the value set is
widened to include `"pending"` and `"running"`. Historical rows with a `null`
value continue to parse correctly (`null` is still a valid member). This is a
**breaking wire rename**: any consumer reading `stage.outcome` must switch to
`stage.status`.

The named schema and type are also renamed:

- `PipelineStageOutcomeSchema` → **`PipelineStageStatusSchema`**
- `TPipelineStageOutcome` → **`TPipelineStageStatus`**

## `responseId` — OpenAI response-id persistence

`PipelineStageSchema` gains `responseId: string | null` — the active attempt's
OpenAI response id. `PipelineStagePayloadSchema` gains the same field at the
per-attempt level. Both are nullable: absent for non-OpenAI stages and for rows
written before this field was introduced.
