# Release notes — v0.54.0

## Fixed

- **The review walk no longer asks you to decide operators on premises you never
  wrote.** A claim that carries at least one citation quietly creates an
  engine-managed premise behind the scenes. Those were being queued up in the
  review flow and shown as ordinary supporting premises, so an argument could
  present more premises to review than it actually has. They are now excluded.
  Note that the number of review steps was never the same thing as the argument's
  premise count and still is not — a conclusion with no operator in it has
  nothing to decide, so it is not a review step.

## Changed

- **Stored free-text fields now declare explicit length limits.** Argument
  titles and descriptions, claim titles and bodies, and moderation notes carry
  caps in the schema itself rather than relying on the server to check them.
  The limits match what the API already enforced, so nothing that was accepted
  before is rejected now. Reading existing content is unaffected — the caps apply
  when writing.
- **Dates are converted with `Value.Decode` instead of `Value.Convert`.** Support
  for typebox 1.3, which removed the base-type API the date schema was built on.
  The accepted input is unchanged — a `Date` or the date string `JSON.stringify`
  produces — but code relying on `Value.Convert` to rehydrate a date now receives
  the string unchanged, with no error, and needs to move to `Value.Decode`.

## Added

- **A text-safe colour for destructive actions.** Destructive controls drawn as
  text or an outline rather than a filled button were below the accessibility
  contrast floor in both light and dark themes. There is now a dedicated colour
  for that case, so those controls can be made readable without turning them into
  loud filled buttons.
