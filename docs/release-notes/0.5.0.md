# Release notes — v0.5.0

This release brings `@proposit/shared` onto `@proposit/proposit-core` ^0.11.0, absorbing both core's v0.10 source-as-claim unification and v0.11 derivation premise discriminator in a single breaking bump. Consumers (proposit-server, proposit-mobile) coordinate on the upgrade — server's wave 1 PR ships the matching DB migration; mobile's bump is a substantive code change.

## What's changed

### Source-as-citation unification (Path A, mirroring core@0.10)

- `TSource` is gone as a separate entity. Citation metadata (URL, IEEE reference, content hash) lives as optional claim-extra fields on `TClaim` records with `type === "citation"`.
- `TClaimSource` is renamed to `TClaimCitation`. Edges have first-class `id` plus `citingClaimVersion` / `sourceClaimVersion` pinning, mirroring core's `CoreClaimCitationSchema`.
- `ArgumentDiff.sources` and `FullArgument.sources` are gone — citation claims show up in the existing `claims` array via the `type` discriminator.
- `ArgumentDiff.claimSources` → `claimCitations`. `FullArgument.claimSources` → `claimCitations`.

### `ClaimSchema.type` field rename

`ClaimSchema.type` (values `"claim" | "conclusion" | "definition" | "criterion"`) is renamed to `kind`, freeing `type` for core's `"normal" | "citation"` discriminator. The const `ClaimTypes` and schemas `ClaimTypesSchema` / `TClaimTypesSchema` rename to `ClaimKinds` / `ClaimKindsSchema` / `TClaimKindsSchema`. `ClaimSearchResultSchema.type` → `kind`.

### Premise type discriminator (mirroring core@0.11)

Every premise now carries a required `type: "freeform" | "derivation"` field. Derivation premises also carry a required `derivedClaimId`. Legacy premise data without `type` is rejected at the schema-parse boundary.

### v0.11 derivation surface re-exports (Level B)

`@proposit/shared/engine/derivation` re-exports `ManagedDerivationPremiseEngine`, `validateDerivationStructure`, `TVariableMaterializer`, and the v0.11 error code constants. No shared-side mutation envelopes around derivation flows yet — those wait for server wave 2.

### Engine API surface

- `PropositArgumentEngine.fromServerData` signature shrinks: `(snapshot, claims, claimCitations)` — `domainSources` parameter removed.
- `getDomainSource` / `getDomainSources` / `setDomainSource` / `removeDomainSource` accessors removed. Citation claims now live in `claimsMap` alongside normal claims; consumers filter `Object.values(claims).filter(c => c.type === "citation")` for citation-only views.
- `addClaimSource` → `addClaimCitation`; `getSourcesForClaim` → `getSourceClaimsForCitingClaim`; `getClaimSources` → `getClaimCitations`; `removeClaimSource(claimId, sourceId)` → `removeClaimCitation(edgeId)` (takes a single first-class edge ID).
- `TProjectReactiveSnapshot.domainSources` field removed.
- `TArgumentEngineSnapshot.sources` field removed.

### REST surface

- `…/claims/${claimId}/source` → `…/claims/${citingClaimId}/citation` (POST).
- `…/source/${sourceId}` (DELETE) → `/citations/${edgeId}` (DELETE).
- `/api/v1/user/sources` → `/api/v1/user/citations` (GET).
- `/api/v1/user/sources/search` → `/api/v1/user/citations/search` (GET).

### Utility + quota renames

- `extractSourceTitle()` → `extractCitationTitle()`.
- `ObjectLimitTypes` literal `"sources"` → `"citations"`.
- `UserTierLimits.maxSourcesPerArg` → `maxCitationsPerArg` across all 7 tier rows.

## Wire/storage shape changes

This section is the load-bearing migration reference for any downstream consumer that persists shapes from `@proposit/shared` into a database, file, message queue, or any other structured store. It is storage-agnostic — it describes form-level deltas and the action a consumer needs to take to bring stored data forward, not specific store commands.

The deltas are organized by entity. Where an entity moves or is absorbed into another, the migration step is called out explicitly.

### Claim records

The Claim entity gains a discriminator and absorbs the former Source entity.

- **Renamed attribute.** Each stored claim record's `type` attribute (values `"claim" | "conclusion" | "definition" | "criterion"`) must be renamed to `kind`. Values are unchanged.
- **New required attribute `type`.** Every claim record now needs a `type` attribute with values `"normal" | "citation"`. Existing claim records that were not previously sources should be backfilled with `type: "normal"`.
- **New optional attributes (citation extras).** When `type === "citation"`, claim records may also carry these attributes. They are absent (or null/undefined) on `type: "normal"` records:
    - `url` (string or null)
    - `citation` (an IEEE reference object; see `TIEEEReference`)
    - `citationContentHash` (string or null)
- **Source records absorbed into claim records.** Each former Source record (see "Source entity (removed)" below) becomes a claim record with `type: "citation"`. Re-use the source's identifier as the new claim's `id` if possible — the citation-edge migration relies on that mapping. Populate `url`, `citation`, and `citationContentHash` from the former source's attributes; populate the standard claim attributes (`text`, `kind`, etc.) from the source's natural-language fields. Pick a `kind` value consistent with how the citation will be referenced (typically `"claim"`).

### Source entity (removed)

The `TSource` / `TSourceNotStrict` entity, plus `SourceSchema*` and the `SourceForkSchema` fork variant, are deleted. There is no longer a separate "sources" collection. After migrating each source record into a `type: "citation"` claim record (see above), the source collection should be dropped.

`SourceForkSchema` is renamed to `CitationForkSchema`. Conceptually, fork records that previously tracked source-entity versions now track citation-edge versions.

### Citation edges (formerly claim-source records)

Records that previously joined a claim to a source — `TClaimSource` — become citation-edge records (`TClaimCitation`). The shape changes as follows.

- **New attribute `id`** (string, required). Citation edges are now first-class entities with their own identifier. Mint a stable ID per edge during migration.
- **Renamed attribute.** `claimId` (the citing claim) is renamed to `citingClaimId`.
- **Renamed/repurposed attribute.** `sourceId` (which previously pointed at the deleted source entity) is replaced by `sourceClaimId`, which points at the citation-typed claim record that the source was migrated into. If the source-record-to-claim-record migration preserved IDs, the value is unchanged; otherwise the migration must remap the old `sourceId` to the new claim's id.
- **New required attribute `citingClaimVersion`** (number). Populate from the citing claim's current version at migration time.
- **New required attribute `sourceClaimVersion`** (number). Populate from the source-side claim's current version at migration time.
- **New required attribute `checksum`** (string). Compute per core@0.10's checksum semantics.
- **Preserved attributes.** `argumentId` (string), `version` (number), and `createdOn` (Date) remain unchanged.

### Premise records (`PropositionalPremiseSchema`)

- **New required attribute `type`** with values `"freeform" | "derivation"`. Backfill all existing premise records with `type: "freeform"` — that is the safe default for legacy data that pre-dates derivation premises.
- **New optional attribute `derivedClaimId`** (string). Required only when `type === "derivation"`; absent on freeform premises.

### `TArgumentEngineSnapshot` (engine snapshot wire format)

- **Removed attribute.** `sources` (was an optional source-manager snapshot). Drop this attribute when reading legacy snapshots; it is no longer accepted at the schema-parse boundary.

### `TProjectReactiveSnapshot` (project reactive snapshot)

- **Removed attribute.** `domainSources` (was a record keyed by source ID). Drop on read.
- **Renamed attribute.** `claimSources` is renamed to `claimCitations`. The element type changes per the citation-edge changes above.

### `ArgumentDiff` (`ArgumentDiffSchema`)

- **Removed attribute.** The `claimSources: { added, removed }` block is removed.
- **Removed attribute.** The `sources: { added, removed }` block is removed.
- **New attribute.** `claimCitations: { added: TClaimCitation[], removed: TClaimCitation[] }` is added. It replaces both removed blocks. When migrating stored diff records, merge the prior `claimSources` and `sources` blocks into the new `claimCitations` block (after reshaping each member per the citation-edge and claim-record rules above).

### `FullArgumentSchema`

- **Renamed attribute.** `claimSources: TClaimSource[]` is renamed to `claimCitations: TClaimCitation[]` (with the element shape changes above).
- **Removed attribute.** `sources: TSourceSchemaNotStrict[]`. Source members move into the existing `claims` array as `type: "citation"` claim records.

### `ClaimWithContextSchema` (`schemas/api/claims.ts`)

- **Removed attribute.** `sources` (optional). Information that previously lived here now lives on the claim record itself (when it is a citation claim) or alongside other claims in any wider context.

### `SourceCreationSchema` → `CitationCreationSchema` (`schemas/api/argument/claims.ts`)

The schema is renamed at the file level. The inner attribute renames are:

- `source: TSourceSchemaNotStrict` → `citation: TClaim` (a citation-typed claim record)
- `sourceRelation: TClaimSource` → `citationEdge: TClaimCitation`

### `ClaimSourceDeleteResponseSchema` → `ClaimCitationDeleteResponseSchema`

Schema renamed at the file level. The inner attribute renames:

- `deletedSources: TClaimSource[]` → `deletedCitations: TClaimCitation[]`

### `SourceUsage*` → `CitationUsage*` (`schemas/api/sources.ts` → `schemas/api/citations.ts`)

The whole file is renamed and symbols inside follow. Notably:

- `SourceWithContextSchema { source, usages }` → `CitationWithContextSchema { citation, usages }`. The renamed `citation` attribute now holds a `ClaimSchema` value (a citation-typed claim record).

### Search response (`schemas/api/search.ts`)

- `SourceSearchRequestSchema` → `CitationSearchRequestSchema`
- `SourceSearchResultSchema` → `CitationSearchResultSchema`
- `SourceSearchResponseSchema` → `CitationSearchResponseSchema`
- Within `EntitySearchResponseSchema`, the `sources` attribute is renamed to `citations`. The element shape follows `CitationSearchResultSchema` (which mirrors the new claim-with-citation-extras shape).

### `ClaimWithChildrenSchema` (`schemas/model/claims.ts`)

- **Renamed attribute.** `childSourceIds` is renamed to `childCitationIds`. Element shape (an array of identifiers) is unchanged.

### User tier limits (`schemas/model/users.ts`, `consts/user-tiers.ts`)

- `ObjectLimitTypes` literal `"sources"` → `"citations"`. Wherever a stored value names the kind of object being limited, replace `"sources"` with `"citations"`.
- `UserTierLimitsSchema.maxSourcesPerArg` → `maxCitationsPerArg`. Rename the attribute on stored tier-limit records; numeric values are unchanged.
- `UserTierLimits` rows in `consts/user-tiers.ts`: every `maxSourcesPerArg` literal renamed to `maxCitationsPerArg` (numeric values preserved).

### Validation codes (`schemas/review.ts`)

- `TCoreValidationCodeSchema` adds a new enum member `DERIVATION_STRUCTURE_INVALID_AT_EVALUATION`. Consumers that switch on the discriminated union may want to add a new branch for the derivation code.
- The four `SOURCE_*` codes remain (still produced by core@0.11). No data migration needed for stored validation-code records.
- The literal `"well-supported-by-sources"` review-reason data string is unchanged. It is preserved as a stable identifier even though the entity has been renamed.

### Relation key changes

- Citation edges are now keyed by their own `id` rather than by `(claimId, sourceId)`. Any store that indexed claim-source records by the composite key should re-key by the new edge `id` after migration.

## Soft-breaking changes

None — every change above is a hard break in 0.5.0. Pre-1.0 versioning policy applies.

## Migration

Downstream consumers (proposit-server, proposit-mobile) bump to `^0.5.0` and migrate their persisted data and code at the same time. Server's wave-1 PR carries the DB migration (drop the sources collection, backfill into the claims collection with `type: "citation"`, rename `claims.type` → `kind`, add the new `claims.type` discriminator, add `propositional_premises.type` and `derived_claim_id`, recompute checksums on claims/premises/arguments/claim-citations). The migration is described in detail in `docs/superpowers/specs/2026-05-06-core-0.11-upgrade-design.md` §9.3. Storage-agnostic deltas are listed in the "Wire/storage shape changes" section above for any consumer not running the server's specific Postgres migration.
