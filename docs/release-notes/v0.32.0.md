# Release notes — upcoming

## Task and pipeline timestamps now say what they mean

Task and pipeline-status fields that used to be called `startedOn`/`completedOn`/`finishedAt`
are now `startedAt`/`settledAt` throughout. `settledAt` is only ever set once a task or
pipeline stage reaches a truly final state (completed, failed, or cancelled) — an
interrupted-but-resumable task no longer gets a timestamp that implies it's done.
Pipeline-stage warnings also move out of the `failures` list into their own `warnings`
list, so "did this stage fail?" no longer requires checking severity.
