# Release notes — v0.56.0

## An exported argument now states the author's claim about its source

When an author builds an argument from a source text, they say whether they are
claiming to reproduce that text faithfully or merely started from it. Until now
that answer appeared in exactly one place — the web app's editing panel, which
only the author sees — so a reader handed a copy of the argument could not tell
the two apart. Telling them apart is the point of the feature.

An exported argument now says it. When the author claimed to be reproducing the
source faithfully, the export carries this line near the top, alongside the
source it names:

> The author says this argument represents that text faithfully.

**When no such claim was made, nothing is emitted.** An author who merely
started from a source says nothing about fidelity, and an argument with no
source text at all exports exactly what it exported before, byte for byte. The
line appears only where the claim was actually made.

In the data, the claim is the origin link's stance: `representation` renders the
line, `seed` renders nothing, and the line is guarded on the origin document as
well, so a claim about a source the export never names cannot render.

The web and mobile apps carry the claim on their own reading surfaces too, in
deliberately parallel wording. All three attribute it to the author — "the
author says …" — rather than stating it as fact, because nothing verifies the
claim and a reader should not come away thinking the platform checked it. Only
the demonstrative differs: the export says "that text", because it names its
source on a separate line, while the apps say "this text", because the source
is on screen beside the claim.

The parallel is a convention held by review, not an invariant: each surface
keeps its own copy of the sentence and nothing asserts the three agree. Pinning
that is worth a later item, not this release.

## `originPassagesFor` is now importable

`@proposit/shared/engine/render` exports the origin passage renderer:

```ts
import { originPassagesFor } from "@proposit/shared/engine/render"

originPassagesFor(snapshot, premiseId)
// → ['Based on origin text "Socrates is a man."']
```

Whether a passage reads that way at all, and whether the source text's
whitespace is collapsed, is a rendering decision more than one surface has to
agree on — the same reason `getInlineSourceLabel` and `describeSource` are
exported from there. A consumer that was keeping its own copy in step with the
export by comment can now delete it.

The snapshot argument is `Pick<TProjectReactiveSnapshot, "origin"> | undefined`,
so a partial snapshot or none is accepted, and the optional `origin` slice is
chained internally — a snapshot rehydrated from pre-origin wire data returns
`[]` rather than throwing.

## Unspoken-step suggestions no longer report the same claim twice

When an argument claims to reproduce its source text, the app offers to mark the
parts that trace back to no passage of it — the steps the original left the
audience to supply. That list was counting things the author cannot see.

Every claim in an argument carries a hidden companion behind the scenes, and the
list walked both. So each claim was offered twice, and every claim added an
extra row reading "an untitled premise" for a premise nobody wrote. A hand-built
argument with one premise and two claims offered six rows. Worse, an imported
argument where every single claim was already linked to a passage — nothing left
unspoken at all — offered sixteen.

Acting on one of the phantom rows was worse than noise: the mark landed on the
hidden companion rather than on the claim, so nothing on screen changed and
there was no way to undo it.

The list now reports one row per premise and one per claim, exactly as they
appear in the argument, and content that is already marked or already linked to
a passage drops out of it as it always should have.

## Repinning

Purely additive. No signature changed, the new export sits on the existing
`./engine/render` subpath, and the export's output changes only for arguments
that already carry a `representation` origin link.
