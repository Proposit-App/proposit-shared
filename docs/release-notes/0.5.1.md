# Release notes — v0.5.1

Patch release. Four schema-level bug fixes against the published `0.5.0` API surface, all surfaced by `proposit-server`'s adoption of `@proposit/shared@0.5.0` during the source-as-claim wave-1 PR. No new features. Full background lives in `docs/change-requests/2026-05-07-publish-0.5.1.md`.

## Bug fixes

### `ClaimSchema.citation` now accepts `null`

`ClaimSchema.citation` was declared `Type.Optional(IEEEReferenceSchema)`. Optional but not nullable — the schema rejected `citation: null` even though Postgres stores `citation: NULL` for normal-type claims (no IEEE reference). Server-side payloads round-trip `null`, so any `ClaimSchema` parse on a normal claim failed. Fix: `Type.Optional(Nullable(IEEEReferenceSchema))`.

### `TClaimCitation` no longer demands a top-level `version`

`ClaimCitationSchema` re-declared a `version: Type.Number()` field on top of `CoreClaimCitationSchema`. The leftover field made no sense — citation edges carry `citingClaimVersion` and `sourceClaimVersion` (both inherited from core), not a single edge-level `version`. The server's renamed `claimCitations` table similarly has no `version` column, so payloads from the server failed validation. Fix: drop the redundant `version` declaration.

### `ArgumentEngineSnapshot` premise `role` is now optional

`OptionalChecksumPremise` (used inside `ArgumentEngineSnapshotSchema`) required `role: "conclusion" | "supporting"` per premise. `proposit-core@0.11` no longer embeds per-premise `role` in the engine snapshot — premise role is tracked at the snapshot root via `conclusionPremiseId`. Round-tripping any v0.11 snapshot through `ArgumentEngineSnapshotSchema` therefore failed. Fix: `role` added to the omit list of the intersect, then re-added as optional in the override layer.

### `CHECKSUM_CONFIG.premiseFields` falls back to the core default

Shared's `CHECKSUM_CONFIG` declared `premiseFields = {argumentId, argumentVersion, role, createdOn, creatorId, title}` — a 6-field hash. Core@0.11's internal `PremiseEngine` strips extra fields before hashing premises and only hashes the 4 core fields (`argumentId`, `argumentVersion`, `type`, `derivedClaimId`). Because of the mismatch, server-recomputed premise checksums diverged from engine-recomputed ones, and stored premise rows failed `checkValidity`. Fix: drop the explicit `premiseFields` override; `createChecksumConfig` falls back to `DEFAULT_CHECKSUM_CONFIG.premiseFields` and the two sides agree.

## Wire/storage shape changes

These changes are all corrections to `0.5.0` rather than new shape introductions. Most consumers will not need to migrate stored data — the changes loosen acceptance, not tighten it.

### Claim records

- **Attribute `citation` now accepts `null`.** Previously `null` would have failed schema validation. Existing rows that store `null` (or any equivalent absence marker) are now valid. No backfill required.

### Citation-edge records (`TClaimCitation`)

- **Attribute `version` removed.** The field was never populated correctly in 0.5.0 anyway (no source of truth). Drop the column or attribute on stored citation-edge records if it exists; consumers that wrote `version` into stored data can ignore it.

### `ArgumentEngineSnapshot` premise data

- **Attribute `role` is now optional.** Stored 0.5.0 snapshots that embedded `role` continue to validate. Snapshots that don't carry `role` per premise — including any snapshot produced by `proposit-core@0.11+` — now also validate. No data migration required; new snapshots simply omit `role`.

### Premise checksums

- **`premiseFields` now hashes only `argumentId`, `argumentVersion`, `type`, `derivedClaimId`.** The four fields previously stripped by the engine but included by the shared override (`role`, `createdOn`, `creatorId`, `title`) are no longer part of the premise checksum. Stored premise rows must have their checksums recomputed against the new 4-field configuration. Consumers that ran 0.5.0 in production briefly need to re-derive `premise.checksum`, `premise.descendantChecksum`, and `premise.combinedChecksum` (and any rolled-up argument `descendantChecksum` / `combinedChecksum` that sits above them).

## Migration

Most consumers can simply bump `@proposit/shared` to `^0.5.1` and continue. The only persisted-data action that may be required:

- If any `0.5.0`-era premise rows were checksummed under the broken 6-field config and persisted, recompute their checksums against the now-correct 4-field config. Re-deriving `premise.checksum`, `premise.descendantChecksum`, `premise.combinedChecksum`, and the parent argument's rollup checksums is sufficient. There are no schema-level changes that require renaming columns or attributes.
