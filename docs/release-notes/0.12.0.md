# v0.12.0 release notes

`v0.12.0` adds the **assign-axiom** mutation helper and api-client
method consumed by the upcoming claim-justification UI in the server's
argument view. Strictly additive — the existing derivation-premise
helpers (`populateDerivationFromCitations`, `clearDerivationAntecedent`,
`mutateCreateDerivationPremise`) are unchanged. No peer-dep bump.

## What's new

- **Engine mutation helper —** `populateDerivationFromAxiom(engine, derivationPremiseId, axiomaticClaim)`
  installs an axiomatic-claim variable as the antecedent of an existing
  derivation premise, producing the `IMPLIES(axiom_var, Q)` shape.
  Mirrors `populateDerivationFromCitations`' composition pattern:
  `clearDerivationAntecedent` first to guarantee an empty slot, then
  wrap the bare consequent in `IMPLIES` with the axiom-bound variable.
  Idempotent on no-op (same axiom already bound); the full clear-and-re-add
  cycle fires when the existing antecedent is a different axiom or a
  citation. Caller registers the axiomatic claim via `engine.setClaim()`
  or `mutateSetClaim()` before invocation — claim-row creation and
  derivation-tree wiring are kept as separable engine operations.

- **API-client method —** `apiClient.createClaimAxiom({ argumentId, version, claimId, axiom })`
  POSTs to the new server-side route
  `POST /api/v1/argument/[argumentId]/[version]/claims/[claimId]/axiom`
  (server-side handler ships in the consuming `proposit-server` slice).
  `claimId` is the **citing** claim — the claim whose derivation premise
  gains an axiomatic backing; the axiomatic claim itself is minted by
  the server from the supplied `axiom: TAxiomKind`.

- **API schemas —** `AxiomAssignmentRequestSchema` (`{ axiom: TAxiomKind }`)
  and `AxiomAssignmentResponseSchema` (`{ axiomClaim, derivationPremise }`)
  added at `@proposit/shared/schemas/api/argument`. Response shape mirrors
  the citation-creation response: the newly-minted entity plus the
  relational context the client needs to wire it into its snapshot
  without a full resync.

## No runtime migration required

This release is purely additive — no existing consumer is broken at
runtime or at the type level. Consumers that don't import the new helper
or call the new api-client method keep working unchanged.

## Versioning intent

Pre-1.0 minor bump (`0.11.1` → `0.12.0`) per the policy in `CLAUDE.md`.
The mutation helper, api-client method, and schemas are additive
features. Peer-dep range on `@proposit/proposit-core` stays at `^1.0.0`
— no engine surface changes in this release; the helper composes on
top of existing public engine APIs (`getPremise`, `ensureClaimBoundVariable`,
`wrapExpression`, plus the same engine accessors the citation helper uses).
