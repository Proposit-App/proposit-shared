# Release notes — v0.53.0

Apps built on this library can now offer account deactivation — the reversible
alternative to deleting an account. A new `deactivateAccount()` client method is
all a consumer needs to add the affordance.

**One breaking change:** the long-redundant `deleted` boolean is gone from the
user schema. Account state has lived on `accountState` since 0.52.0, which says
whether an account is active, deactivated, banned or deleted rather than
collapsing all four into one flag. Anything still reading `user.deleted` should
compare `user.accountState` to `"deleted"`.
