# Release notes — v0.42.1

## Deleting a claim reaction survives an evolving reason-code set

Removing a claim reaction whose stored `reasonCode` has fallen out of the closed
reason-code union no longer fails the delete response. Such a value is carried
through as a raw string, matching the read-path behavior shipped in 0.38.1.
Adding a reaction is unchanged — it still requires a known reason code, and its
response can only echo a just-written, currently-valid code — so only the delete
response is affected. For consumers, the removed `reasonCode` type widens to
`string`.
