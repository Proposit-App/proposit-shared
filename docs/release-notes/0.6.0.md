# Release notes — v0.6.0

Minor release. Adds a derivation-premise mutation surface that `proposit-server` wave 2 needs to build engine-validated `IMPLIES(OR(citation_var_*, …), Q)` antecedent trees through the standard `mergeChangesets` / `persistChangeset` flow. Background: `docs/change-requests/2026-05-07-derivation-premise-mutations.md`.

## Why this is minor (and not patch)

Three new public exports under `@proposit/shared/engine/mutations`. The pre-1.0 versioning policy says minor bumps may include breaking changes, but this release is purely additive — existing freeform-premise mutations and exports are unchanged. Consumers pinned at `^0.5.1` can move to `^0.6.0` without code changes; consumers that don't yet need derivation premises can ignore the new exports entirely.

## What's new

### `mutateCreateDerivationPremise`

Atomic create for a derivation premise. The naked-Q form (single variable expression at the root) is the only valid empty-antecedent shape per `ManagedDerivationPremiseEngine.assertWellFormed()`; this mutation produces it in one go alongside the underlying claim-bound consequent variable. All three IDs (`premiseId`, `consequentVariableId`, `consequentExpressionId`) are caller-controlled.

```ts
const { premise, consequentVariable, consequentExpression, changes } =
    mutateCreateDerivationPremise(engine, uuidv4(), {
        argumentId,
        argumentVersion,
        creatorId,
        createdOn: new Date(),
        derivedClaimId: claim.id,
        consequentVariableId: uuidv4(),
        consequentExpressionId: uuidv4(),
    })
await persistChangeset(trx, argumentId, argumentVersion, changes)
```

**Why caller-minted IDs:** `proposit-server`'s migration uses raw-SQL backfill (no engine context). Letting the live write-path mint IDs the same way as the migration keeps the two paths producing structurally identical rows, which simplifies post-migration verification.

**Implementation note:** `engine.createPremiseWithId({ type: "derivation", … })` auto-mints a consequent variable + naked-Q expression with engine-generated IDs. The mutation runs that, then surgically swaps the auto IDs for the caller-minted ones (remove + re-add) and filters the auto entries out of the merged changeset. Net effect on the engine's internal state is identical to the engine's auto-init; net effect on the changeset is that only the caller-minted IDs are reported.

### `clearDerivationAntecedent`

Removes the IMPLIES + antecedent subtree from a populated derivation premise. Cascades through `OR` (when present) and citation-bound variables. Idempotent on already-naked premises (returns an empty changeset).

```ts
const { changes } = clearDerivationAntecedent(engine, derivationPremiseId)
```

Throws `DERIVATION_TYPE_MISMATCH` if the premise isn't a derivation premise. The implementation removes the antecedent subtree first (cascade=true), then removes the IMPLIES root with cascade=false so the consequent variable expression "promotes" to root (its `parentId`/`position` become a `modified` entry).

### `populateDerivationFromCitations`

Builds the `IMPLIES(antecedent, Q)` shape on a naked-Q premise:

- `sourceClaimIds.length === 0` → no-op (empty changeset).
- `sourceClaimIds.length === 1` → `IMPLIES(citation_var_1, Q)`.
- `sourceClaimIds.length >= 2` → `IMPLIES(OR(citation_var_1, …, citation_var_n), Q)`. The OR sits directly under IMPLIES (no formula buffer) — the mutation temporarily switches the premise to `PERMISSIVE_GRAMMAR_CONFIG` for the wrap, mirroring the technique used by core's `ManagedDerivationPremiseEngine.populateFromCitations`.

```ts
const sourceClaimIds = await trx("claimCitations")
    .where({ citingClaimId, citingClaimVersion: version, argumentId })
    .orderBy("createdOn")
    .pluck("sourceClaimId")
const clear = clearDerivationAntecedent(engine, derivationPremiseId)
const populate = populateDerivationFromCitations(
    engine,
    derivationPremiseId,
    sourceClaimIds
)
const merged = mergeChangesets(clear.changes, populate.changes)
await persistChangeset(trx, argumentId, argumentVersion, merged)
```

Throws:

- `DERIVATION_TYPE_MISMATCH` — premise isn't `type='derivation'`.
- `DERIVATION_ANTECEDENT_NON_EMPTY` — premise root is already an IMPLIES (caller forgot to call `clearDerivationAntecedent` first).

**Why caller-supplied source-claim IDs:** the engine's `claimCitationLibrary` is set to `EMPTY_CLAIM_SOURCE_LOOKUP` in server's `constructEngineFromData`, so an in-engine lookup wouldn't find anything. Server queries `claimCitations` from Postgres directly and passes the resolved `sourceClaimId`s to the mutation. The same shape supports the migration's raw-SQL backfill (which queries the same source table).

### `buildTextTree` filters derivation premises

Wave 2's ATV view shows freeform premises in the flat text walk and renders derivation premises as citation badges + naked-Q indicators on claim cards. The text walk now skips premises with `type === "derivation"` — purely additive for arguments without derivation premises.

## Internal helpers

`premises.ts` adds three private helpers used by the new mutations:

- `withoutEntities(changes, omit)` — strips entries with the given variable/expression IDs from `added`/`modified`/`removed`. Used to drop engine-auto-generated entities before merging.
- `sanitizeAddedThenModified(changes)` — drops every entity that appears in `added` from `modified` of the same category. Required because core's `createPremiseWithId` for derivation type emits the new premise in BOTH `added` (outer collector) AND `modified` (the inner naked-Q `appendExpression` pushes a `modifiedPremise` entry as the premise's checksum changes). Both entries describe the same row; the `added` row reflects the latest data so the `modified` entry is redundant.
- `mergeChangesetSequence(changesets)` — safer batched merge that drops `modified` entries for any entity that's `added` somewhere in the sequence. Required because sequential `appendExpression` calls report descendant-checksum changes on previously-added parents (e.g. an OR added in step N gets reported as `modified` in step N+1 when a child is appended), which would otherwise trip `mergeChangesets`'s single-bucket invariant.

These are deliberately not exported — they're a workaround for two upstream mismatches (core's mixed-bucket changeset emission and the lack of a public derivation-init bypass). When `@proposit/proposit-core` exposes either, these helpers can be removed.

## Wire/storage shape changes

None. This release adds new public functions; no schemas, no checksum configs, no exports were changed.

## Migration

Bump `@proposit/shared` to `^0.6.0`. No code changes required for consumers that don't use the new mutations. Consumers that DO use them (i.e., `proposit-server` wave 2) should consult the change request for the composition pattern (`addClaim`, `addClaimCitation`, citation-removal, migration backfill).
