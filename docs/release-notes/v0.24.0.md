# Release notes — v0.24.0

This release tightens argument-delete authorization, moves user settings under
an extensible `preferences` object, and adds an optional machine-readable
`errorCode` to the error envelope.

- **Argument hard-delete is OWNER-only among participants.** A collaborator with edit access (EDITOR) can edit an unpublished draft but can no longer delete it — only the draft's owner (or a holder of `argument:delete` / `admin:full-access`) can. Consumers that gate the delete affordance on `canArgument("delete", …)` pick this up automatically.
- **User settings moved under `preferences`.** `TUser.advancedMode` is replaced by `TUser.preferences.advancedMode`, and `UserModifyRequest` now takes a partial `preferences` patch. A new extensible `UserPreferencesSchema` backs it, so future settings need no schema churn. Consumers reading `user.advancedMode` must read `user.preferences.advancedMode`; updaters send `{ preferences: { advancedMode } }`.
- **Optional `errorCode` on the error envelope.** `ErrorResponseSchema` gains an optional `errorCode` string so endpoints can attach a stable machine-readable code (e.g. a retry-refusal reason) and clients branch on it instead of parsing the message. Additive — responses that omit it stay valid.
