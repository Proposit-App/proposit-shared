# v0.15.1 release notes

This release lands the `@proposit/shared` half of **slice D** of the
pipeline-refinement initiative (post-v0.17.2 design): a canonical 402
error-body contract for token-budget exhaustion. Additive only — a new
schema sub-entry, no peer-dep changes, no behavior change to existing
schemas.

## What's new

- **`@proposit/shared/schemas/api/errors`** — new sub-entry exporting the
  canonical 402 body shape:
    - `BudgetExceededErrorBodySchema` — the body emitted by every
      LLM-bearing entry route in `proposit-server` (argument build, plus
      the twitter / reddit / raw_text imports) when the caller's per-user
      token budget is exhausted. Discriminated by
      `code: "TOKEN_BUDGET_EXCEEDED"` and carrying
      `usage: { used, limit, resetOn }` so the client can surface the
      budget state to the user. Replaces the previous ad-hoc
      `{ errorMessage, errorID, statusCode }` body that gave the client no
      way to distinguish a budget overrun from any other 402-class
      failure.
    - `TBudgetExceededErrorBody` — the derived TypeScript type.

## Schema-design notes for consumers

- The literal `code` matches the **task-level** settle code used for
  mid-pipeline overruns (`TaskStatus.FAILED` with
  `errorData.code === "TOKEN_BUDGET_EXCEEDED"`) — same classifier across
  the request-level body (this schema) and the task-level failure.
- `usage.used` and `usage.limit` are **non-negative integers**;
  `usage.resetOn` is an **ISO-8601 date-time**. Format on `resetOn` is
  enforced by `Value.Parse`, not `Value.Check` (the repo's standard
  TypeBox convention — `Check` validates type, `Parse` validates format).

## Peer-dep range

No peer-dep changes. The schema is self-contained TypeBox and adds no
`@proposit/proposit-core` surface.

## Consumer migration

None required — the new sub-entry is additive. `proposit-server` flips
its `@proposit/shared` dep to `^0.15.1` when adopting slice D (adds a
`createBudgetExceededErrorResponse` helper, replaces the 402 emission in
the four LLM-bearing routes, and adds per-route specs).
`proposit-mobile` is not a direct consumer today, but the
tarball-validation gate still applies before publish.

## Versioning

Pre-1.0 patch bump (`0.15.0` → `0.15.1`) — purely additive (new module +
export entry), no breaking change to existing schemas.
