# v0.10.0 release notes

`v0.10.0` is the small coordinated minor that unblocks server's cycle 4b (advanced-mode setting) and cycle 4c (validation gates) in the cross-repo Grammar Tiers initiative (spec at `proposit-orchestration/docs/superpowers/specs/2026-05-13-grammar-tiers-design.md`). Three additions only — no engine-wrapper churn, no peer-dep bump.

## Breaking — `UserModifyRequest.username` is now optional

`UserModifyRequest` at `src/schemas/api/user/index.ts` changed from `Type.Object({ username: Type.String() })` to:

```ts
export const UserModifyRequest = Type.Object({
    username: Type.Optional(Type.String()),
    advancedMode: Type.Optional(Type.Boolean()),
})
```

The body becomes "any one writable field" rather than always-username. Callers that always passed `username` continue to validate, but the wire-level "username is required" constraint is gone — server enforces "at least one writable field present" as an out-of-schema concern. Mobile and server callsites need to adapt if they relied on TypeScript narrowing `username` to non-undefined after `parseRequest`.

## New — `UserSchema.advancedMode: boolean`

`UserSchema` at `src/schemas/model/users.ts` gains a required `advancedMode: Type.Boolean()` field. Per-user grammar-tiers behavior toggle:

- `advancedMode: false` (the default) → engine runs in `'assistive'` behavior; server enforces `validate('derivable')` on submit/save and rejects with the 422 grammar-violations envelope.
- `advancedMode: true` → engine runs in `'permissive'` behavior; server skips the derivable gate, and violations surface inline for the user to resolve.

The wire perspective is "required field on every user response"; the DB-side `NOT NULL DEFAULT false` column is owned by server's coordinated cycle-4b migration.

## New — `isGrammarViolationsError()`

New file `src/api-client/grammar-violations.ts` exports a runtime type-guard:

```ts
import { isGrammarViolationsError } from "@proposit/shared/api-client"

if (isGrammarViolationsError(err)) {
    // err is TGrammarViolationsResponse — render `err.violations` inline
}
```

Narrows an unknown value to `TGrammarViolationsResponse` via the stable `error: "GRAMMAR_VIOLATIONS"` discriminator. Re-exported alongside `createApiClient` from `@proposit/shared/api-client`. Sits next to the existing `parseResponse` overload form (`parseResponse(resp, SuccessSchema, GrammarViolationsResponseSchema)`); use the guard at callsites where the error originates from a wider union (caught `unknown`, or a `TErrorResponse | TGrammarViolationsResponse` boundary).

## Versioning intent

Pre-1.0 minor bump (`0.9.0` → `0.10.0`) per the policy in `CLAUDE.md`. The `UserModifyRequest.username` optional flip is the breaking-behavior driver under the pre-1.0 minor-may-break rule. Consumers picking up `0.10.0` do not need to bump `@proposit/proposit-core` — the peer-dep range stays at `^1.0.0`.
