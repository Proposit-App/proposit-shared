# Upcoming release notes

Patch release. Fixes a load-side invariant violation in `PropositArgumentEngine.fromServerData` that prevented `proposit-server`'s argument-view path from rendering any argument whose underlying snapshot contains a wave-2 derivation premise (`IMPLIES(OR(c1, c2, …), Q)` — i.e., any non-conclusion claim with two or more citations). Background: `docs/change-requests/2026-05-08-fromServerData-relaxed-load-grammar.md`.

## Why this is patch (and not minor)

Pure bug fix. No public API surface change, no signature change, no behavior change for valid inputs that previously succeeded — only previously-throwing snapshots now load.

## What was wrong

`fromServerData` constructs the engine and then calls `engine.rollback(snapshot)` to restore state. Inside `rollback`, proposit-core's `ArgumentEngine` runs `validate()` after the snapshot is materialized, and that validation checks each `ExpressionManager`'s grammar config. proposit-core's `ExpressionManager.fromSnapshot` resets the manager's config back to the snapshot's stored config after loading, so even though `rollback` passes `PERMISSIVE_GRAMMAR_CONFIG` for the load itself, post-load validation runs under whatever grammar was in effect when the snapshot was originally captured — typically the strict runtime grammar (`enforceFormulaBetweenOperators: true`).

Wave-2 derivation premises produced by `populateDerivationFromCitations` for `n ≥ 2` citations carry an `IMPLIES(OR(c1, c2, …), Q)` shape — exactly the `OR` directly under `IMPLIES` nesting that strict grammar rejects. So any argument with at least one multi-citation claim failed to load.

This is the same dual-grammar discipline mistake that `proposit-server`'s `constructEngineFromData` (against `ArgumentEngine.fromData`) already corrects on its side; the snapshot/rollback path needed the equivalent fix.

## What changed

`PropositArgumentEngine.fromServerData` (in `src/engine/engine.ts`):

1. Constructs the engine with a `RUNTIME_GRAMMAR` (`enforceFormulaBetweenOperators: true`, `autoNormalize: false`).
2. Before calling `engine.rollback(snapshotWithVariableConfig)`, rewrites every `premises[].expressions.config.grammarConfig` to a `LOADING_GRAMMAR` (`enforceFormulaBetweenOperators: false`). This is the only way to influence what grammar the post-load `ExpressionManager` config retains, because proposit-core's `ExpressionManager.fromSnapshot` overwrites whatever grammar was used during loading with the snapshot's own config when it returns. Top-level `snapshot.config.grammarConfig` is preserved so that the engine's own grammar stays strict after rollback (which governs new premise creation).
3. After rollback, iterates `engine.listPremises()` and calls `pe.setGrammarConfig(RUNTIME_GRAMMAR)` so each restored `PremiseEngine` enforces the strict grammar for runtime mutations (`addExpression`, `wrapExpression`, etc.).

Two new module-private constants in `src/engine/engine.ts` capture the dual-grammar split: `RUNTIME_GRAMMAR` and `LOADING_GRAMMAR`.

## Migration impact

- **`proposit-server`** — `src/app/(nofooter)/view/[argumentId]/[version]/build-combined-provider-data.ts` and any other call site routed through `fromServerData` now succeed for wave-2 multi-citation arguments. Bump the `@proposit/shared` dependency to this release.
- **`proposit-mobile`** — same fix applies; no source change required.
