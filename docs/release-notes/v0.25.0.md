# Release notes — v0.25.0

This release decouples the claim schema from the argument version so claims can
be modeled as first-class, independently-versioned entities that are shared by
reference across arguments. It is the schema/type half of the
independently-versioned-claims work; the publish/fork/search behavior lands in
proposit-server. **Breaking** (minor bump per the pre-1.0 policy).

- **`claims.version` is now the claim's own trunk version.** It is no longer a
  denormalized copy of the referencing argument's version — it advances only when
  the claim's own content changes, and different arguments may pin different
  versions of the same claim. No structural change to the field (still a number);
  the doc comment now states the new semantics.
- **`argumentId` → nullable `originArgumentId` (breaking).** A shared claim is no
  longer owned by a single argument; this field is provenance only — the argument
  the claim was first created in — and may be null. Consumers reading
  `claim.argumentId` must read `claim.originArgumentId` (now `string | null`).
- **New `published` + `publishedOn` on every claim (breaking).** Per-claim-version
  publish state: `published: boolean` (a `v0` draft is `false`) and
  `publishedOn: Date | null`. Both are required fields on all three claim variants
  (`publishedOn` is nullable but must be present).
- **`ClaimForkSchema` / `TClaimFork` are now exported.** The claim-fork provenance
  type already existed but was re-exported nowhere; it is now importable from
  `@proposit/shared/schemas` (parallels the existing `ArgumentForkSchema` export).
  No new export sub-path — it surfaces through the existing `./schemas` entry.
