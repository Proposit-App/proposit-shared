# Upcoming release notes

### Bug fixes

- Four GET endpoints in `@proposit/shared/api-client` now pass the absolute URL (origin + path + query) to the consumer-supplied `fetchImpl`, instead of a path-only string: `getAllArguments`, `getUserSources`, `getUserClaims`, and `getExpressions`. The path-only form relied on browser `fetch()` resolving against `window.location.origin`, so it worked on `proposit-server` (web) but failed on `proposit-mobile` (React Native, no `window.location`) with `TypeError: Network request failed`. Reported by `@proposit/proposit-mobile` during Phase 1 / 1F simulator validation against `getAllArguments`; the audit caught three more endpoints with the same pattern. Each endpoint now has a regression test asserting the URL handed to `fetchImpl` parses cleanly with origin `=== baseUrl`. Once published, mobile can revert its temporary diagnostic workaround in `useArgumentsList`.
