# v0.12.2 release notes

`v0.12.2` is a maintenance patch over `v0.12.0`. (The `v0.12.1` tag was
retired pre-publish; this release supersedes it and additionally folds
two dual-review findings against the C-bundle commits — see the new
"Internal cleanup" section below.) Three follow-ups from the 2026-05
server-refinements sweep land:

- a review-evaluation bugfix that resolves "Indeterminate" verdicts on
  arguments that should evaluate cleanly under post-Grammar-Tiers 1.0
  semantics,
- a schema widening that admits axiomatic claims through the
  `ClaimWithChildrenSchema` surface (the server stopped narrowing to
  `type='normal'` in the wave-2 axiom-mutation slice),
- an engine-mutation hardening that lifts the server's cycle-5 extras-sync
  workaround inside `@proposit/shared` so mobile and any other engine
  consumer get the same guarantee.

No breaking changes. No peer-dep range bumps.

## What changed

- **Review evaluation no longer returns spurious "Indeterminate".** The
  shared review path now routes through `argEngine.evaluate(...)` and
  `argEngine.checkValidity(...)` directly, so the engine's safety nets —
  axiomatic-bound variables forced to `true` before evaluation, naked-Q
  derivation premises filtered out of the eval context — fire as they do
  for non-review engine consumers. The manually-constructed evaluation
  context (`toEvaluationContext`) is still used by
  `canonicalizeOperatorAssignments` and now mirrors core's naked-Q filter.
  Axiom-bound variables are skipped from the assignment map the review
  path builds, so the engine's `AXIOM_VARIABLE_ASSIGNMENT_FORBIDDEN` guard
  no longer trips on caller-supplied keys.

- **`ClaimWithChildrenSchema` accepts axiomatic claims.** Widened from
  `NormalClaim`-only to `NormalClaim | AxiomaticClaim`. Citation claims
  remain rejected (citations are leaf entities and carry no children).
  Server's `getClaims()` dropped its `type='normal'` filter in the wave-2
  R5 slice; the schema now matches that wire format. Consumers that
  pattern-matched assuming `NormalClaim`-only get a wider union — most
  call sites pass through unchanged because they were already accepting
  whatever the server returned.

- **`mutateUpdatePremiseRole` keeps `extras.role` in sync atomically.**
  Core's `setConclusionPremise(id)` and `clearConclusionPremise()` only
  touch the engine's `conclusionPremiseId` slot — they leave the affected
  premise's `extras.role` stale. The shared mutation now syncs the
  target premise's `extras.role` to the new role, and (when promoting a
  different premise to conclusion) demotes the prior conclusion's
  `extras.role` to `"supporting"`. Server consumers can drop the
  bracketing `sharedUpdatePremiseExtras({ role })` calls in
  `model/logic.ts updatePremise()` (the Grammar-Tiers-cycle-5 workaround);
  the helper is now atomic on its own.

## Internal cleanup (fold over C-bundle)

Two dual-review findings against the C-bundle commits were folded before
publish:

- **Diagnostic dump removed from `evaluateArgumentForReview`.** The
  `console.log` / `console.warn` pair (and the now-unused
  `buildEvaluationDebugPayload` helper) that the C1 investigation added
  to `src/engine/review/evaluation.ts` is gone. The bug the dump was
  added to investigate was closed by the C1 engine-routing fix in this
  same cycle; the dump fired on every wizard operator click both
  browser-side and SSR.
- **`mutateUpdatePremiseRole` no-op contract restored.** When the
  engine's role-state and the premise's `extras.role` both already match
  the requested role, the helper short-circuits and emits an empty
  changeset (`{ changes: {} }`). The C3 extras-sync fix made the helper
  unconditionally re-emit `modifiedPremise` (and a `roles` changeset in
  the conclusion→conclusion path); the short-circuit restores the
  pre-C3 no-op behavior for the truly-idle case. The self-consistency
  predicate is conservative: if `extras.role` has drifted from
  role-state (the reason this helper exists), the short-circuit is
  false and the sync paths run as before.

## Out of scope

- The server-side cleanup of the cycle-5 extras-sync workaround is a
  separate change in `proposit-server` that ships once it bumps its
  `@proposit/shared` dep to `^0.12.2`.

## Versioning

Pre-1.0 patch bump (`0.12.0` → `0.12.2`; `v0.12.1` was retired before
publish). The two helper changes are additive-with-stricter-defaults —
call sites get more-correct behavior without changing their call shape.
The schema widening is additive at the union level. The fold tightens
the no-op contract on `mutateUpdatePremiseRole` and removes an
internal-only diagnostic dump. Peer-dep range on
`@proposit/proposit-core` stays at `^1.0.0`; this release leans on the
engine's existing safety-net behaviors but adds no new core API
requirements.
