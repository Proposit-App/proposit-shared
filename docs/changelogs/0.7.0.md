# Upcoming changelog

Minor release. Drops the `PERMISSIVE_GRAMMAR_CONFIG` bypass in two derivation-premise mutations so the wave-2 antecedent ships in the canonical formula-buffered shape.

## `@proposit/shared/engine/mutations`

- `populateDerivationFromCitations` (`src/engine/mutations/premises.ts`): removed the `withGrammarConfig(pm, PERMISSIVE_GRAMMAR_CONFIG, …)` save/restore around the IMPLIES + OR + citation-var construction. Standard grammar runs throughout, so the engine's `wrapInsertFormula` auto-normalize rule auto-inserts a formula buffer between IMPLIES and OR. Output shape changes from `IMPLIES(OR(c1, …, cn), Q)` (shape A) to `IMPLIES(formula(OR(c1, …, cn)), Q)` (shape B) — the canonical shape every other engine path produces — for `n ≥ 2`. `n = 0` and `n = 1` are unchanged.
- `clearDerivationAntecedent` (same file): removed the `withGrammarConfig(pm, PERMISSIVE_GRAMMAR_CONFIG, …)` wrapper around `removeExpression(IMPLIES, false)`. Added a `formula` branch to the antecedent dispatch that walks `formula → OR → citation_var children` to collect citation-bound variable ids; cascade-remove (`removeExpression(antecedent.id, true)`) handles the formula and OR removal in one shot. The `variable` (n=1) and `operator/or` (legacy n≥2) branches stay so `clearDerivationAntecedent` continues to work on shape-A snapshots loaded through the `LOADING_GRAMMAR` shim.
- Internal cleanup: the now-unused `withGrammarConfig` helper and the `PERMISSIVE_GRAMMAR_CONFIG` / `TGrammarConfig` imports from `@proposit/proposit-core` are dropped from `premises.ts`.

## `@proposit/shared/engine` (load path)

- `PropositArgumentEngine.fromServerData` is unchanged. It continues to rewrite each per-premise expression config to `LOADING_GRAMMAR` (`enforceFormulaBetweenOperators: false`) before `rollback`'s `validate()` pass and re-tighten to `RUNTIME_GRAMMAR` afterwards. The shim is intentionally retained as the back-compat path for unmigrated shape-A rows and is independent of the construction-time fix in this release.
- `validateDerivationStructure` is unchanged. Both shape A and shape B are valid per-premise structurally, so pre-v0.7.0 stored trees still load.
