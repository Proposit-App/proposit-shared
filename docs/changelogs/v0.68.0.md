## Added

**Unowned-argument reads on the api-client.** `getUnownedArguments()` returns the
signed-in caller's claimable arguments and `getUnownedArgument(argumentId,
version)` returns one unowned entry, both wired in `createApiClient`. The write
half (`claimUnownedArgument`) already existed; the read half did not, so no client
could reach a claimable argument in order to claim it. `getUnownedArguments`
answers `TArgument[]` — the list route returns full arguments, not
`UnownedArgument` rows — matching what `proposit-server`'s profile list already
renders. Empty, not an error, when there is nothing to claim. No new schema was
needed.

**`searchUsername(username)` on the api-client.** Resolves a handle to a public
profile (`userId`, `username`, `imageURI`) over `GET /api/v1/user/search`, using
the existing `UsernameSearchRequest`/`UsernameSearchResponse` schemas. Only the
factory method was missing: the web app calls that route directly from a Server
Component, so a client method had never been needed. Handles are encoded once via
`URLSearchParams`, which matters because curated persona handles contain spaces and
a slash.

**Premise operator-reaction methods, and their schemas.**
`createOperatorReaction`, `deleteOperatorReaction`, and a bulk
`getOperatorReactionMap(argumentId, version)` that seeds a whole reading surface in
one request, mirroring the existing `getClaimReactionMap`. The request/response
schemas move out of the server's route folder into
`@proposit/shared/schemas/api/operator-reaction`, so both clients read one
contract instead of the server owning the shape privately. Response shape is
unchanged, so adopting the client is a no-op for the web app.

**`@proposit/shared/engine/origin-authoring`.** The pure decisions the source-text
authoring surface makes, promoted from `proposit-server`: `utf16ToCodePoint` and
`selectionToCodePointSpan` (the UTF-16 → code-point conversion every selection API
forces, since origin offsets count code points), `isMarkableExpression`,
`isMarkedUnspoken`, `describeTarget`, `allAnchorsForTarget`, and
`isAttributionEditable`. They import only `@proposit/proposit-core` and the engine,
touch no DOM, React, Next or React Native, and lived in the server repo only
because the server got there first. The reading-half counterparts were already
federated under `engine/render`; this is the authoring half.

`isAttributionEditable` accepts `… | null | undefined` — the server's two copies
disagreed about their own types, and the shared signature admits both callers
uncast.

**Seven capability declarations in the master**, for cross-platform behaviors the
web app shipped that no capability described: curated showcase content, the
readership lean on a claim or premise, inline respond-in-support, the topic tag,
status-and-shape while reading, your body of work counted, and the
superseded-version notice. All seeded `Missing`; consumers assert their own status.

## Notes

The origin-authoring promotion leaves `proposit-server` holding a now-duplicate
local copy, and `proposit-mobile` a third. Both delete theirs on adoption, which
requires this release — that is the follow-up, not an oversight.
