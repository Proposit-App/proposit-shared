# Changelog — v0.52.0 (`d9dc752..c545b8f`)

- **Add the account-state axis.** `AccountStates` (`"active"`, `"deactivated"`,
  `"banned"`, `"deleted"`), its TypeBox schema (`AccountStatesSchema`,
  `AllAccountStates`, `TAccountStates`, `TAllAccountStates`) in
  `src/schemas/model/users.ts`, and a required `accountState` field on
  `UserSchema`. `@proposit/shared/consts` additionally exports
  `LOCKED_OUT_ACCOUNT_STATES` and `isLockedOut(accountState)` from a new
  `src/consts/account-states.ts`; `AccountStates` resolves from both
  `@proposit/shared/consts` and `@proposit/shared/schemas`.

    String values rather than the numeric encoding `tier` uses: the field is read
    in queries, logs, and admin payloads where `"banned"` beats `101`.

    `LOCKED_OUT_ACCOUNT_STATES` is `BANNED` and `DELETED` only. **`DEACTIVATED`
    is deliberately not locked out** — signing in is how a deactivated account
    reactivates, so authentication has to succeed for it. `isLockedOut` takes a
    `string`, not the narrow union, for the same reason its predecessor took a
    `number`: values arrive off database rows where the declared type is an
    assertion rather than a validated parse, and failing closed on an unknown
    principal is the caller's job.

- **BREAKING: remove `isPlatformDisabled` and `PLATFORM_DISABLED_TIERS`** (added
  in v0.51.0). Not renamed, not aliased, not re-pointed at the new axis.
  `DEACTIVATED` inverts meaning here — it was platform-disabled and must stop
  being so — and a consumer that repinned while still compiling against the old
  name would silently inherit backwards behaviour. Removing the symbols makes the
  compiler find every call site. `proposit-server` imports it at two sites and
  will not build until it moves to `isLockedOut(accountState)`.

- **BREAKING: `UserTiers` is entitlement-only.** `BANNED` (101) and `DEACTIVATED`
  (102) are removed from `UserTiers` and `UserTiersSchema`, and their all-zero
  rows are removed from `UserTierLimits` and `UserTierNames`
  (`src/consts/user-tiers.ts`). Entering a state no longer destroys a user's
  entitlement, so an unban restores the account at the tier it was paying for.

    **`NO_ASSIST` keeps the value `103`.** The numbers are persisted, so closing
    the gap left below it would silently re-map existing rows.

- **BREAKING: `UserSchema.accountState` is required.** A `TUser` value now has to
  carry a state. `UserSchema.deleted` is untouched and still required — the
  server retires it in a later step, once no reader remains.
