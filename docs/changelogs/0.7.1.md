# 0.7.1 changelog

Patch release. `mutateCreateDerivationPremise` grows an `existingConsequentVariableId` parameter so callers can adopt an already-existing claim-bound variable as the consequent rather than minting a duplicate. The change is fully backwards-compatible at the call-site level — existing callers that pass `consequentVariableId` continue to work identically.

## `@proposit/shared/engine/mutations`

- `mutateCreateDerivationPremise` (`src/engine/mutations/premises.ts`): signature gained an optional `existingConsequentVariableId: string` and `consequentVariableId` is now optional. The two parameters are mutually exclusive — callers must supply exactly one. Adopt mode validates that the named variable is in the engine, is claim-bound, and is bound to `derivedClaimId`; the merged changeset's `variables.added` does not contain a new claim-bound variable for `derivedClaimId` (the existing one is reused). Mint mode (callers passing `consequentVariableId`) is unchanged. Implementation leans on `engine.ensureClaimBoundVariable`'s reuse behavior — `createPremiseWithId({ type: "derivation", … })` surfaces the existing claim-bound variable as the auto consequent when one is in scope, so adopt mode only removes the auto naked-Q expression and skips the explicit `removeVariable`/`addVariable` pair the mint path runs.

## Tests
