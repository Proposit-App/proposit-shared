# Changelog — v0.6.2

Commit range: `v0.6.1` → `v0.6.2`. Patch release fixing a `mergeChangesets` invariant violation in `clearDerivationAntecedent` that fires whenever the mutation runs against an engine reconstructed via `rollback(snapshot)`.

## Bug fixes (`@proposit/shared/engine/mutations`)

- `clearDerivationAntecedent` no longer throws `mergeChangesets: entity "<id>" appears in both modified and removed in expressions` when invoked after an engine reload (e.g. the server's per-request `loadArgumentData` + `rollback(snapshot)` flow). The internal `mergeChangesetSequence` helper now drops `modified` entries whose ids appear in any sub-changeset's `removed` bucket, symmetric to its existing `added`/`modified` reconciliation. Background: `docs/change-requests/2026-05-08-clear-derivation-modified-removed-conflict.md`.

## Tests

- Extended: `src/engine/mutations/__tests__/derivation-premises.test.ts` — adds two regression tests covering the reload boundary: (1) `clear` on an n=1 IMPLIES(c, Q) after `snapshot/rollback`; (2) the full clear → populate cycle that mirrors the server's `addClaimCitation` flow when reshaping n=1 → n=2.
