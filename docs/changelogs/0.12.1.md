## Engine — review evaluation

- **Modify:** `src/engine/review/evaluation.ts` — `evaluateArgumentForReview`
  routes through `argEngine.evaluate(assignment, options)` instead of the
  standalone `evaluateArgument(toEvaluationContext(...), ...)`.
  `checkValidityForReview` routes through `argEngine.checkValidity(options)`.
  Both engine methods apply two safety nets the standalone path missed:
  (1) `applyAxiomaticForcedAssignments` pre-pass that forces axiomatic-
  claim-bound variables to `true`, and (2) `asEvaluationContext()`-driven
  naked-Q derivation premise filter that drops scaffold premises out of
  the eval surface. `buildExpressionAssignment` now also skips axiom-
  bound variables when constructing the variables map (the engine's
  pre-pass rejects any caller-supplied key for them via
  `AXIOM_VARIABLE_ASSIGNMENT_FORBIDDEN`). `toEvaluationContext` is kept
  for `canonicalizeOperatorAssignments`' use and mirrors core's naked-Q
  filter so the operator-canonicalization surface sees the same view of
  premises that the engine's internal eval context uses. Commit `a541d08`.
- **Add:** `src/engine/review/__tests__/evaluation.test.ts` — 2 new
  regression tests in the `evaluation` describe block. Coverage:
  axiom-bound conclusion variable with no user assignments (engine forces
  to `true`, conclusion verdict is definite), naked-Q scaffold premise in
  a supporting position (filter excludes it, conclusion verdict is
  definite). Commit `a541d08`.
- **Modify:** `src/engine/review/__tests__/fixtures.ts` —
  `buildEngineWithAxiomaticConclusion` and
  `buildEngineWithNakedQSupportingPremise` fixture builders added.
  Helper `makeAxiomaticClaim` (file-local) constructs an axiomatic-
  variant `TClaim` for the engine's `setClaim` call. Commit `a541d08`.

## Schemas — claim union widening

- **Modify:** `src/schemas/model/claims.ts` — `ClaimWithChildrenSchema`
  widened from a single `Type.Interface([NormalClaimSchema], { ... })`
  to a `Type.Union([...])` of two branches: one keyed on `NormalClaimSchema`
  and one on `AxiomaticClaimSchema`. Both branches carry the same
  `childClaimIds: Type.Array(UUID)` and `childCitationIds: Type.Array(UUID)`
  appendages. Citations remain excluded (leaf entities). Docstring
  rewritten — the pre-fix wording referenced the `getClaims()`
  `type='normal'` filter the server dropped in wave-2 R5. Commit `2468d1d`.
- **Modify:** `src/schemas/__tests__/claims.test.ts` — 4 new tests in a
  new `ClaimWithChildrenSchema` describe block. Coverage: normal-with-
  children accepted, axiomatic-with-children accepted, citation rejected,
  missing children-id arrays rejected. Commit `2468d1d`.

## Engine — premise role-state extras sync

- **Modify:** `src/engine/mutations/premises.ts` —
  `mutateUpdatePremiseRole` now synchronizes `extras.role` on every
  branch through the helper. Core's `setConclusionPremise(id)` and
  `clearConclusionPremise()` only update the engine's
  `conclusionPremiseId` slot; the affected premise's `extras.role`
  stayed at whatever it was at creation. Three sync sites are now
  handled atomically:
  (1) target premise's `extras.role` matches the requested `newRole`,
  (2) when promoting a new conclusion, the prior conclusion's
  `extras.role` is demoted to `"supporting"`,
  (3) even when the engine's role-state slot already matches the request,
  `extras.role` is still synced as defense-in-depth.
  Subsumes the cycle-5 server workaround in
  `proposit-server/src/model/logic.ts updatePremise()` (the bracketing
  `sharedUpdatePremiseExtras({ role })` calls). Implementation factors
  the sync into a private `syncPremiseExtrasRole(engine, premiseId,
role)` helper that lookup-elides missing premises (returns
  `{ changes: {} }`). Commit `335d691`.
- **Modify:** `src/engine/mutations/__tests__/premises.test.ts` — 3 new
  tests in the `mutateUpdatePremiseRole` describe block. Coverage:
  promoting a supporting premise to conclusion writes `extras.role:
"conclusion"`, demoting a conclusion to supporting writes
  `extras.role: "supporting"`, promoting a fresh premise to conclusion
  demotes the prior conclusion's `extras.role` to `"supporting"`. Commit
  `335d691`.

## Sweep findings

- C3's audit confirmed `mutateCreatePremise` was already extras-coherent
  at the role-state slot — it passes `role` via `extras: data` to
  `createPremiseWithId`, so the new premise's `extras.role` and the
  engine's `conclusionPremiseId` are aligned from the start. No fix
  needed there. The patch scope ended up being a single mutation entry
  point (`mutateUpdatePremiseRole`) with an internal demote-the-prior-
  conclusion case that the briefing's three-sentence sketch implied but
  did not enumerate.
- C2's widening flagged no internal narrowing inside `@proposit/shared`
  itself (no consumer of `TClaimWithChildren` lives in this repo outside
  test fixtures). Server-side narrowings, if any, surface at the server
  agent's next typecheck pass.
- C1's diagnostic dump (`console.log("[review:evaluation]", ...)` in
  `evaluateArgumentForReview`) was left in place. The bug it was added
  to investigate is now fixed, but the dump's removal is a separate
  housekeeping concern — it's still useful as a one-line trigger for
  future review-evaluation regressions and adds no failure modes.
