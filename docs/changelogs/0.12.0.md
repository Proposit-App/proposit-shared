# v0.12.0 changelog

`v0.12.0` adds the assign-axiom flow's shared-side contract: a new
mutation helper, an api-client method, two TypeBox schemas, and the
factory wiring. Strictly additive — no breaking changes at the type or
runtime level. Commit range on the wave-2 branch:
`f25e123..0961b1f` (4 commits) plus the version-bump commit landing
this changelog.

## Engine mutation surface

- **Add:** `src/engine/mutations/premises.ts` —
  `populateDerivationFromAxiom(engine, derivationPremiseId, axiomaticClaim): { changes: ProjectChangeset }`.
  Composition mirrors `populateDerivationFromCitations`:
  `clearDerivationAntecedent` first to guarantee a naked-Q root, then
  `pm.wrapExpression(IMPLIES, axiom_variable, undefined, consequentExpr.id)`
  to build the `IMPLIES(axiom_var, Q)` antecedent shape. The n=1 form
  needs no formula buffer, so no engine-behavior flip (the citation
  helper's `engine.setBehavior('permissive')` window for n≥2 is not
  reused). Idempotency short-circuit (`isAlreadyAxiomBacked`) returns an
  empty changeset when the current root is already `IMPLIES(axiom_var, Q)`
  with the antecedent variable resolving to a claim-bound variable for
  `axiomaticClaim.id`. Runtime guard on
  `axiomaticClaim.type === 'axiomatic'` catches mis-typed casts past the
  TypeScript boundary. Commit `4d602b1`.
- **Modify:** `src/engine/mutations/index.ts` — re-exports the new helper
  from `./premises.js` alongside the existing derivation-premise helpers.
  Commit `4d602b1`.

## API-client surface

- **Add:** `src/api-client/argument/claims.ts` —
  `createClaimAxiomImpl(config, { argumentId, version, claimId, axiom })`.
  POSTs to `/api/v1/argument/${argumentId}/${version}/claims/${claimId}/axiom`
  with body `{ axiom }` validated through `AxiomAssignmentRequestSchema`
  and response validated through `AxiomAssignmentResponseSchema` via
  `strictFetch`. Args object shape (not positional) matches the
  architect-locked signature in the S3 spec §11. Commit `9376b6d`.
- **Modify:** `src/api-client/factory.ts` — registers
  `createClaimAxiom: createClaimAxiomImpl` in the `impls` map so the
  factory-derived `TApiClient` mapped type surfaces
  `apiClient.createClaimAxiom(...)` automatically. Commit `9376b6d`.

## Schemas

- **Add:** `src/schemas/api/argument/claims.ts` —
  `AxiomAssignmentRequestSchema` (`Type.Object({ axiom: AxiomKindSchema })`)
  and `AxiomAssignmentResponseSchema`
  (`Type.Object({ axiomClaim: AxiomaticClaimSchema, derivationPremise: PropositionalPremiseSchema })`).
  Imports `AxiomaticClaimSchema` and `AxiomKindSchema` from
  `src/schemas/model/claims.ts` (already in place; no schema-model
  changes needed) and `PropositionalPremiseSchema` from
  `src/schemas/logic.ts`. The response shape mirrors the citation-creation
  response: new entity + relational context the client wires into its
  snapshot. Commit `f25e123`.

## Note on the cycle-1-briefing signature naming

The cycle-1 briefing item-2 named the api-client `axiom` argument as
`axiom: TAxiomaticClaim`. The authoritative S3 spec §11 (cross-repo
contract) consistently uses `axiom: TAxiomKind` for both the wire format
(`AxiomAssignmentRequestSchema`) and the api-client signature — the
server mints the full axiomatic-claim row from the kind; the client
never holds a `TAxiomaticClaim` before this POST. The implementation
follows the S3 spec on this conflict and the changelog entry above
documents the resolution. Surfacing here so the reviewer has the
historical context.

## Tests

- **Add:** `src/engine/mutations/__tests__/derivation-premises.test.ts` —
  8 new tests in a `populateDerivationFromAxiom` describe block.
  Coverage: naked → axiom-backed (`IMPLIES(axiom_var, Q)`), snapshot/
  rollback round-trip, citation-backed → axiom-backed (verifies the
  clear-then-populate flow removes the prior citation antecedent),
  idempotency on same-axiom re-apply (empty changeset, unchanged
  checksum), distinct-axiom replacement (full churn), DERIVATION_TYPE_MISMATCH
  on non-derivation premise, clear error on missing premise, runtime
  rejection of non-axiomatic claim. Helper `mkAxiomaticClaim` co-located
  inside the test file (mirrors `mkTestClaim` shape). Commits `f25e123`
  (RED) + `4d602b1` (GREEN). Final tests: 333 → 341 (+8 net).
- **Add:** `src/api-client/argument/__tests__/create-claim-axiom.test.ts` —
  2 new tests. Coverage: happy-path POST shape (URL, method, JSON body
  plus strict-fetch response parsing) and malformed-response-body
  rejection through the response schema validator. Tests: 341 → 343
  (+2 net). Commit `9376b6d`.
