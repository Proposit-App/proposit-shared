# v0.13.0 changelog

`v0.13.0` lands the `proposit-shared` half of the ingestion-pipeline
initiative (Phase 1). Three implementation commits on the
`ingestion-pipeline/phase-1` branch:

- Slice 1E (`a410110`): schemas and `@proposit/proposit-core` dep bump.
- Slice 1E.A (`7ef95a1`): `mutateUpdatePremiseRole` demote refusal —
  sync to core@1.0.2's E-7 invariant.
- Slice 1E.B (`8011b55`): `mutateCreatePremise` extras-sync to
  `"conclusion"` on first-premise auto-assign, plus a test assertion
  pinning the `ARGUMENT_NO_CONCLUSION` violation code.

Merge commit on `main`: `6d493d1` (`--no-ff` to preserve slice
structure). Plus the docs/release-prep commit landing these notes and
the `pnpm version` commit landing the version bump.

Initiative: "Ingestion pipeline framework". Briefing at
`docs/superpowers/briefings/ingestion-pipeline-proposit-shared-agenda.md`.
Cross-repo overview at
`proposit-orchestration/docs/superpowers/specs/2026-05-22-ingestion-pipeline-overview.md`.

## Schemas — new ingest-argument task-input and ProcessingFailure re-export

- **Add:** `src/schemas/ingest-argument/index.ts`. Exports
  `IngestionPipelineVersionSchema`
  (`Type.Union([Type.Literal("v1-single-shot"), Type.Literal("v2-multi-stage")])`),
  `IngestArgumentTaskInputSchema`
  (`{ text: String(minLength:1, maxLength:50_000), pipelineVersion, title?, description? }`),
  and the two derived types `TIngestionPipelineVersion`,
  `TIngestArgumentTaskInput`. **Internal contract** — not a public
  route schema. Server route handlers construct this from the public
  `CreateArgumentSchema` body plus the server-side
  `INGESTION_PIPELINE_VERSION` env, then pass to `executePipeline(...)`
  in `@proposit/proposit-core`. Commit `a410110`.
- **Add:** `src/schemas/processing-failure.ts` — type-only re-export
  of `TProcessingFailure` from `@proposit/proposit-core`. Same
  template as `src/schemas/grammar/index.ts`. Core@1.1.1 ships only
  the TS type (no TypeBox `ProcessingFailureSchema` value yet); the
  file's header comment documents the future-extension path when
  core adds the runtime schema. Commit `a410110`.
- **Add:** `src/schemas/ingest-argument/__tests__/index.test.ts` — 14
  TypeBox `Value.Check` round-trip tests covering valid minimal,
  valid with optional fields, invalid version literal, empty text,
  50,000-char boundary (accept) and 50,001-char (reject), missing
  required fields, non-string types. Commit `a410110`.
- **Add:** `src/schemas/__tests__/processing-failure-reexport.test.ts`
  — 1 compile-time `expectTypeOf` assertion that the re-exported
  `TProcessingFailure` is structurally identical to core's. Commit
  `a410110`.
- **Modify:** `package.json`. Two new sub-entry `exports`:
  `./schemas/ingest-argument` and `./schemas/processing-failure`,
  alphabetically slotted between `./schemas/grammar` and the
  `./schemas/*` wildcard. Each declares `types`, `import`, and

## Engine — `mutateUpdatePremiseRole` demote refusal (E-7 sync)

- **Modify:** `src/engine/mutations/premises.ts`. The
  demote-the-current-conclusion branch now throws
  `InvariantViolationError` carrying a single violation entry with
  `code: "ARGUMENT_NO_CONCLUSION"`, `entityType: "premise"`,
  `entityId: premiseId`, `premiseId`, and an informative message.
  The previous implementation called the now-no-op
  `engine.clearConclusionPremise()` followed by an inconsistent
  `syncPremiseExtrasRole(..., "supporting")`, silently desyncing
  the engine slot from `extras.role`. The promote-to-conclusion
  branch is unchanged — it atomically replaces the conclusion at
  the engine slot AND syncs both premises' extras-roles in one
  shot. The no-op short-circuit at the head of the helper still
  fires for already-in-state requests and prevents the throw from
  triggering on a `"conclusion" -> "conclusion"` self-call. Reuses
  core's `ARGUMENT_NO_CONCLUSION` code (same code core's
  `validateArgumentEvaluability` emits at `argument-validation.js:267`)
  rather than minting a new helper-specific code. Commit `7ef95a1`.
- **Modify:** `src/engine/mutations/__tests__/premises.test.ts`.
  Removed two pre-E-7 tests (`clears conclusion role` and `syncs
extras.role to 'supporting' when demoting from conclusion`) that
  asserted behavior no longer reachable through any path through
  the helper. Added two replacement throw-tests covering the
  single-premise variant (`throws InvariantViolationError when
demoting the sole conclusion (E-7)`) and the multi-premise
  variant (`throws InvariantViolationError when demoting the
conclusion alongside other premises (E-7)`). Each asserts both
  the throw and the post-throw engine state (engine slot unchanged,
  extras.role unchanged on both target and any sibling premise).
  Commit `7ef95a1`.

## Engine — `mutateCreatePremise` first-premise extras-sync (E-7 mirror)

- **Modify:** `src/engine/mutations/premises.ts`. The
  create-supporting-as-first-premise branch (the second arm of
  `mutateCreatePremise`'s role-switch, where the engine has
  auto-assigned the new premise as conclusion despite a
  non-`"conclusion"` caller request) replaced the no-op
  `engine.clearConclusionPremise()` call with a
  `syncPremiseExtrasRole(engine, premiseId, "conclusion")` call.
  When core auto-assigns the first premise as conclusion (the
  "auto-conclusion assignment" rule, unchanged across the 1.0.x
  range), the helper now syncs `extras.role` to `"conclusion"` to
  match the engine slot — rather than letting `extras.role` retain
  the caller's `"supporting"` request and creating drift. The merge
  uses the existing `withoutPremiseModifications` helper to strip
  the redundant `modifiedPremise` entry that `updateExtras` emits
  (the outer `createPremiseWithId` already added the premise in
  its own changeset; same pattern already in
  `mutateCreateDerivationPremise`). Inline comment rewritten to
  describe actual behavior accurately. Commit `8011b55`.
- **Modify:** `src/engine/mutations/__tests__/premises.test.ts`.
  Rewrote `creates a supporting premise` to `first premise
auto-assigns as conclusion regardless of requested 'supporting'
role (E-7)`. Asserts `engine.getConclusionPremise()?.getId() === premiseId`,
  `result.premise.role === "conclusion"`, and
  `engine.getPremise(premiseId)?.toPremiseData().role === "conclusion"`,
  locking the no-drift contract on first-premise creation. Added
  `second premise with 'supporting' role stays supporting (no
auto-conclusion override)` to lock in the post-first-premise
  path where the helper correctly preserves the caller's
  `"supporting"` intent (the auto-conclusion rule fires only when
  no conclusion exists). Commit `8011b55`.

## Test — `ARGUMENT_NO_CONCLUSION` code assertion

- **Modify:** `src/engine/mutations/__tests__/premises.test.ts`.
  The two slice-1E.A throw-tests now assert
  `(caught as InvariantViolationError).violations[0].code === "ARGUMENT_NO_CONCLUSION"`
  via a try/catch and `expect(caught).toBeInstanceOf(InvariantViolationError)`
  pattern (replacing the prior class-only `toThrow(InvariantViolationError)`
  pattern). Server route handlers (slice 1G) pattern-match on this
  code to map to 409; locking the contract via a test prevents
  accidental rename. Commit `8011b55`.

## Out of scope

- The api-client wrapper at `src/api-client/ingest-argument.ts` is
  deferred per the initiative spec (§14 item 11). The path is
  reserved but no typed wrapper ships in 0.13.0.
- The runtime `ProcessingFailureSchema` TypeBox value re-export is
  blocked on core shipping it; a future shared minor will land it
  when core adds the runtime schema.
- Server consumer updates (call-site rewrites for the
  demote-then-promote pattern, plus 409 mapping for
  `ARGUMENT_NO_CONCLUSION`) ship in `proposit-server` slice 1G,
  separate dispatch. Reviewer identified the two known call sites:
  `model/logic.ts:1264-1283` and
  `arg-data-context/premise-actions.ts:117-138`. Mobile has zero
  `mutateUpdatePremiseRole` callers; its dep bump (slice 1I) is
  dep-only.
