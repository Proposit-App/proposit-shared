# Changelog — v0.42.1

## Changed

- `ClaimReactionDeleteResponse.removedReaction.reasonCode` loosened to tolerate a
  value that has fallen out of the closed reason-code union, via a response-only
  variant of the reaction shape
  (`Type.Intersect([Type.Omit(ClaimReactionSchema, ["reasonCode"]), Type.Object({ reasonCode: Type.Union([ClaimReasonCodeSchema, Type.String()]) })])`).
  This matches the read-path loosening shipped in 0.38.1
  (`ClaimReactionSelectionSchema.reasonCode`): a delete that echoes a persisted
  row whose code has since been retired is now carried through as a raw string
  instead of 500'ing on strict response validation. The model
  (`ClaimReactionSchema`) is left strict, as is the create response — its
  `addedReaction` only ever echoes the row just written from the strict
  `ClaimReactionCreateRequest`, so a retired code cannot reach it — and the write
  path stays the closed union. Consumer-visible: the removed `reasonCode` static
  type widens to `string`.
