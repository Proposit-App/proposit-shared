# v0.9.0 changelog

`v0.9.0` is the grammar-tiers minor of `@proposit/shared`, the second slice of the cross-repo Grammar Tiers initiative. The branch landed in two phases: 14 pre-pivot commits (authoring grammar schemas locally + adding the 422 envelope + mutation-generator commentary, against the pre-2026-05-14 design that had wire-format ownership in shared) and the post-pivot reset (this changelog's primary scope) that aligns shared with core 1.0's surface after the wire-format ownership pivot.

## Package — peer dep bump (breaking)

- **Bump:** `peerDependencies['@proposit/proposit-core']` and `devDependencies['@proposit/proposit-core']` from `^0.12.3` to `^1.0.0` (one commit). Consumers must bump core in lockstep when picking up shared `0.9.0`.

## Engine — wrapper refactor against core 1.0

- **Modify:** `src/engine/engine.ts` (`PropositArgumentEngine`):
    - Drop the `TGrammarConfig` import + the `RUNTIME_GRAMMAR` / `LOADING_GRAMMAR` constants + the per-engine `grammarConfig` constructor option (replaced by core 1.0's `behavior: 'assistive' | 'permissive'` setting, default `'assistive'`).
    - Switch the reactive-snapshot invariant sweep from `this.validate()` (split in 1.0) to `this.validateInvariants()`, preserving the legacy `{ ok, violations }` semantics.
    - `fromServerData`: drop the per-premise expression-config rewrite to `LOADING_GRAMMAR` and the post-rollback `pe.setGrammarConfig(RUNTIME_GRAMMAR)` re-tightening loop. Core 1.0's snapshot-loading contract accepts any Structural-valid state.
    - Rename the domain claim accessor from `getClaim(id)` to `getProjectClaim(id)` to avoid colliding with core's promoted `getClaim(claimId, claimVersion)` on the `ArgumentEngine` base. Both methods now coexist on `PropositArgumentEngine`: callers wanting the minimal `TCoreClaim` use `getClaim(id, version)`; callers wanting the rich `TClaim` use `getProjectClaim(id)`.
- **Modify:** `src/engine/derivation.ts` — drop re-exports of `ManagedDerivationPremiseEngine` (D1 deletion), `DERIVATION_STRUCTURE_INVALID_AT_EVALUATION` (D4 deletion), `DERIVATION_ANTECEDENT_NON_EMPTY` (D3 deletion), `TVariableMaterializer` (MDPE-only). Add re-exports of `CREATE_DERIVATION_REQUIRES_DERIVED_CLAIM_ID` and `CREATE_DERIVATION_CLAIM_NOT_FOUND`. Module-level comment explains the post-1.0 surface + migration target.
- **Modify:** `src/engine/optimistic/verification.ts` — drop the `grammarConfig` option on the temporary `serverEngine` used for checksum comparison.
- **Modify:** `src/engine/review/review-engine.ts` — `dropStaleAssignments` switches from `argEngine.getClaim(id)` to `argEngine.getProjectClaim(id)`.
- **Modify:** `src/schemas/review.ts` — `TCoreValidationCodeSchema` swaps `DERIVATION_STRUCTURE_INVALID_AT_EVALUATION` for `DERIVATION_STRUCTURE_INVALID` to match core 1.0's runtime emitter.

### Behavior change: `populateDerivationFromCitations` for n ≥ 2

- **Modify:** `src/engine/mutations/premises.ts` — the legacy helper still functions but its n ≥ 2 branch now flips the engine to `'permissive'` for the duration of the build (`engine.setBehavior('permissive')` → wrap + per-citation appends → restore prior behavior). The output shape changes from the pre-1.0 canonical formula-buffered `IMPLIES(formula(OR(c1, …, cn)), Q)` to the unbuffered `IMPLIES(OR(c1, …, cn), Q)` — Structural-valid but P-1-noncompliant. Strengthen the `@deprecated` JSDoc with migration target (core 1.0's `engine.populateFromCitations` / `engine.populateFromAxioms`) and explicit removal target (shared `^1.0.0`).
- **Decision (briefing §2):** kept the helper rather than deleting. Rationale: IMPLIES/OR tree construction uses unchanged mutation surface; deletion would force server's lone callsite into a same-cycle migration AND delete a substantial test suite for the build semantics. Documented in the release notes.

## Schemas — pre-restructure files deleted, re-export added

- **Delete:** `src/schemas/grammar/tier.ts`, `src/schemas/grammar/rule-code.ts`, `src/schemas/grammar/violation.ts` — the pre-restructure local schema files. Equivalent symbols now ship from `@proposit/proposit-core@^1.0.0`.
- **Delete:** `src/schemas/__tests__/grammar-{tier,rule-code,violation}.test.ts` — tests for the local-author surface. Equivalent coverage in core's own grammar-types suite.
- **Add:** `src/schemas/grammar/index.ts` — re-export module exposing `GrammarTierSchema`, `GrammarRuleCodeSchema`, `ViolationSchema`, `TGrammarTier`, `TGrammarRuleCode`, `TViolation` from `@proposit/proposit-core`.
- **Add:** `src/schemas/__tests__/grammar-reexport.test.ts` — regression suite asserting re-export identity (same object as core's), runtime validation behavior, and TypeScript-level type equivalence via `expectTypeOf`.
- **Modify:** `src/schemas/api/grammar-violations.ts` — re-point imports from the deleted `../grammar/tier.js` + `../grammar/violation.js` to the new `../grammar/index.js`. The 422 envelope's runtime shape is unchanged.

## Test fixture changes

- **Modify:** `src/engine/mutations/__tests__/helpers.ts` — `createTestEngine()` returns the engine in `'permissive'` behavior so incremental tree-build patterns (operator root → child → child) don't trip core 1.0's AN-3. Tests that need AN explicitly opt back in via `engine.setBehavior('assistive')`.
- **Modify:** `src/engine/review/__tests__/fixtures.ts` — `buildEngineWithTwoPremises()` constructs the engine with `behavior: 'permissive'` (new `TLogicEngineOptions` field), builds the trees, then flips back to `'assistive'` before returning.
- **Modify:** `src/engine/mutations/__tests__/derivation-premises.test.ts` — multiple test rewrites for the new contracts (formula-buffer assertions split into "helper produces unbuffered" + companion "after normalize() the buffer materializes"; `pm.setGrammarConfig` → `engine.setBehavior`; `fromSnapshot(snapshot, lookup, { autoNormalize, ... })` → `fromSnapshot(snapshot, lookup)` + explicit `engine.normalize()` for the fixed-point assertion; the after-load "still respects strict grammar" assertion → "inherits the default assistive behavior").
- **Modify:** `src/engine/__tests__/derivation.test.ts` — drop the pre-1.0 MDPE assertions; assert on the surviving re-export surface.
- **Modify:** `src/engine/__tests__/engine.test.ts` — claim-accessor tests switch from `engine.getClaim(id)` to `engine.getProjectClaim(id)`.
