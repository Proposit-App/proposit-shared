# Changelog — v0.6.0

Commit range: `v0.5.1` → `v0.6.0`. Minor release adding a derivation-premise mutation surface that lets `proposit-server` wave 2 build engine-validated `IMPLIES(OR(citation_var_*, …), Q)` trees through the standard `mergeChangesets` / `persistChangeset` flow.

## New mutations (`@proposit/shared/engine/mutations`)

- `mutateCreateDerivationPremise(engine, premiseId, data)` — atomically creates a derivation premise + claim-bound consequent variable + naked-Q variable expression. All three IDs are caller-controlled so the live engine path produces the same row IDs as the server's raw-SQL migration backfill.
- `clearDerivationAntecedent(engine, premiseId)` — strips the IMPLIES/OR antecedent subtree from a populated derivation premise, leaving the premise in naked-Q form. Idempotent for already-naked premises. Cascades citation-bound variable removals.
- `populateDerivationFromCitations(engine, premiseId, sourceClaimIds)` — builds `IMPLIES(citation_var, Q)` for n=1 or `IMPLIES(OR(citation_var_1, …, citation_var_n), Q)` for n≥2 on top of a naked-Q premise, using the supplied source-claim ID list (caller-supplied so the engine's `claimCitationLibrary` can stay empty in server's `constructEngineFromData`). Throws `DERIVATION_TYPE_MISMATCH` / `DERIVATION_ANTECEDENT_NON_EMPTY` for invalid call sites.

## Engine helpers

- `buildTextTree` (`src/engine/text-tree.ts`) now skips premises with `type === "derivation"` — these surface as citation badges + naked-Q indicators on claim cards in wave-2's ATV view, and shouldn't emit `premise-header → operator → claim` items in the flat text walk.

## Tests
