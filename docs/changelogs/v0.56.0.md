# Changelog — v0.56.0

<changes starting-hash="c99121a" ending-hash="f521172">

## Added

- `originPassagesFor(snapshot, targetId)` is exported from
  `@proposit/shared/engine/render`. It returns the quoted origin passages one
  target of an argument was written from — `Based on origin text "…"`, with the
  source text's whitespace collapsed — and `[]` whenever there is no origin
  data. Previously module-private to `src/engine/render/markdown.ts`, which
  meant every reading surface showing a passage on screen carried its own copy
  of the lead-in and the collapsing, kept in step by nothing but a comment.
  `snapshot` is typed `Pick<TProjectReactiveSnapshot, "origin"> | undefined`, so
  a caller holding a partial snapshot, or none, needs no wrapper. No new
  `exports` subpath — `./engine/render` already existed.
- `serializeArgumentToMarkdown` states the author's fidelity claim when the
  argument's origin link carries stance `representation`: the header blockquote
  gains the line `The author says this argument represents that text faithfully.`,
  after the passage and attribution lines. Guarded on the origin _document_, not
  just the link, so a claim about a source the export never names cannot
  render.

## Changed

- `anchorsFor` in `src/engine/render/markdown.ts` is gone; both of its call
  sites now go through `originPassagesFor`, which is the new public entry point
  on `./engine/render`. `originPassage` remains as the single-anchor helper
  `originPassagesFor` maps over, but it changed from module-private to
  `export`, so it is incidentally reachable as
  `@proposit/shared/engine/render/markdown` through the `./engine/*` wildcard.
  It is not part of the documented surface — import `originPassagesFor` from
  `./engine/render` instead. Behaviour preserving; the export goldens are
  unchanged by the extraction.

## Fixed

- `deriveEnthymemeSuggestions` and `deriveEnthymemeContradictions` no longer
  walk engine-synthesized derivation premises. `markableContent` iterated every
  premise in the snapshot, and a persisted claim carries a derivation premise of
  its own whose consequent expression binds the same claim-bound variable the
  authored expression does — so each claim was reported twice, and each claim
  contributed a titleless premise the author never wrote. Measured on a live
  argument: 1 authored premise + 2 claims produced 6 suggestions, and a Scholar
  import with 11 anchors covering all 7 of its claims produced 16 once its
  stance was set to `representation`, where the correct answer is zero — a mark
  and an anchor land on the authored expression only, so the shadow expression
  passed both the marked and the anchored guard. Acting on one of those rows
  wrote a real `enthymeme` mark onto an entity nothing renders, which therefore
  could not be un-marked. Both derivations now yield only content present in the
  authored snapshot; `text-tree` already skipped derivation premises the same
  way.

## Notes

- The markdown export is byte-identical to v0.55.0 for every argument that does
  not carry a `representation` origin link — verified against the pre-change
  renderer for four shapes: no origin slice at all, an empty slice, a link that
  survived without its document, and a full document with anchors under stance
  `seed`, which emits nothing extra by design.
- Purely additive. `serializeArgumentToMarkdown`'s signature is unchanged and
  `originPassagesFor` is a new named export on an existing subpath, so nothing
  breaks on repinning.
