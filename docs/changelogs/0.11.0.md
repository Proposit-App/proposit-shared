# v0.11.0 changelog

`v0.11.0` is the client-side half of the Grammar Tiers 422-envelope
plumbing — `parseResponse` learns to auto-detect the
`GRAMMAR_VIOLATIONS` envelope and return it as a typed branch of its
discriminated return. One source change, one downstream test fix, eight
new tests.

## API-client — `parseResponse` 422 auto-detect

- **Modify (breaking, type-level):** `src/utils/utils.ts` — `parseResponse`
  2-arg overload widens its return type from
  `ParsedSuccess<T> | ParsedError<typeof ErrorResponseSchema>` to
  `ParsedSuccess<T> | ParsedError<typeof ErrorResponseSchema> | ParsedError<typeof GrammarViolationsResponseSchema>`.
  On HTTP 422 the implementation runtime-checks the body via
  `Value.Check(GrammarViolationsResponseSchema, data)`; on match it
  parses and returns the typed envelope, otherwise it falls back to
  `ErrorResponseSchema` (pre-0.11 behavior). 3-arg overload (explicit
  error schema) is unchanged — bypasses the auto-detect. Commit `1a4b9fd`.

## Tests

- **Add:** `src/utils/__tests__/utils.test.ts` — 8 tests for the new
  `parseResponse` behavior. 2-arg form covers: 200 success (unaffected),
  422 + GRAMMAR_VIOLATIONS (typed envelope), 422 + empty-violations
  publish-gate body (typed envelope), 422 + non-grammar body
  (TErrorResponse fallback), 401 non-422 failure (TErrorResponse,
  unaffected), 200 + malformed success body (throws, unaffected). 3-arg
  form covers: explicit schema bypasses auto-detect (still parses
  grammar body via caller-supplied schema), 3-arg + 200 success
  (unaffected). Commit `1a4b9fd`.
- **Modify:** `src/api-client/user/__tests__/delete-user.test.ts` —
  narrows the discriminated union via `"errorMessage" in result.error` /
  `"statusCode" in result.error` checks before accessing those legacy
  `TErrorResponse` fields on the 401 + 500 paths. The 401 and 500 cases
  always land in the `TErrorResponse` branch (auto-detect is 422-only),
  so the narrow is guaranteed at runtime. No behavior change. Commit
  `b53ba44`.
