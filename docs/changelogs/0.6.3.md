# Upcoming changelog

Patch release fixing a `PropositArgumentEngine.fromServerData` invariant violation that prevents loading any argument whose snapshot contains a wave-2 derivation premise (`IMPLIES(OR(c1, c2, …), Q)`).

## Bug fixes (`@proposit/shared/engine`)

- `PropositArgumentEngine.fromServerData` no longer throws `EXPR_FORMULA_BETWEEN_OPERATORS_VIOLATED: Non-not operator "or" expression "<id>" is a direct child of operator "<id>"` when the snapshot contains a derivation premise produced by `populateDerivationFromCitations` with `n ≥ 2` citations. The factory now relaxes `enforceFormulaBetweenOperators` for the rollback's `validate()` pass and re-tightens `RUNTIME_GRAMMAR` on every restored `PremiseEngine` afterwards, so wave-2 derivation shapes load cleanly while subsequent runtime mutations still respect the explicit-formula-between-operators discipline. Background: `docs/change-requests/2026-05-08-fromServerData-relaxed-load-grammar.md`.

## Tests

- Extended: `src/engine/mutations/__tests__/derivation-premises.test.ts` — adds four `fromServerData` load-side regression tests: (1) loading an `IMPLIES(OR(c1, c2), Q)` snapshot does not throw; (2) the wave-2 shape round-trips through the engine after restore; (3) `RUNTIME_GRAMMAR` is re-applied on restored premises (a re-snapshot carries `enforceFormulaBetweenOperators: true`); (4) a pre-wave-2 `IMPLIES(citvar, Q)` snapshot still loads identically.
