# v0.26.0

- **`PropositArgumentEngine` rejects citation/axiomatic claims in freeform premises (load-time invariant).** `src/engine/engine.ts` now throws when a `citation`- or `axiomatic`-typed claim is used as a node in a freeform (`IMPLIES`/logical) premise — such claims belong only in derivation premises. This is the load-time safety net behind the ingestion-side deterministic sort: a class of malformed arguments now fails with a clear error at construction instead of crashing downstream.
- **Citation claim shape cleaned.** `CitationClaimSchema` (`src/schemas/model/claims.ts`) models `citation` as a non-nullable `Union([IEEEReference, UnparsedCitation])` with a nullable `url`, replacing the prior nullable-citation shape. Consumers decoding citation jsonb must handle the `type: "unparsed"` branch; a url-less citation is `url: null`, not `""`.
- **Claim-versioning API surface.** New `@proposit/shared/schemas/api/argument/versioning` schemas (`ClaimLatestVersionResponseSchema`, `AdvanceClaimReferenceRequestSchema`, `AdvanceClaimReferenceResponseSchema`) and `createApiClient` methods `getLatestClaim`, `getLatestClaimVersion`, `advanceClaimReference` — fetch a claim's latest published version (`GET /claim/[claimId]/latest`), check whether a newer published version exists, and advance a draft argument's claim reference to a newer version.
- **Derivation-premise claim-version pin + nullable claim-fork id.** The derivation-premise schema (`src/schemas/logic.ts`) gains an optional nullable `derivedClaimVersion` (FK pin `(derivedClaimId, derivedClaimVersion) → claims(id, version)`); `ClaimForkSchema.forkId` (`src/schemas/model/forks.ts`) is now nullable for claim-only forks, which have no `argumentForks` row to reference. The premise mutation (`src/engine/mutations/premises.ts`) supports the new pin.

> Pre-1.0 policy: this minor bump includes breaking schema changes (the citation shape). Pin with `^0.26.0`.
