# Changelog — v0.37.0

## Added

- `GetCurrentUserResponse` + `TGetCurrentUserResponse`
  (`src/schemas/model/users.ts`): the current-user read shape — `usage` + `limits`
  (as in `GetUserUsageDataResponse`) plus the caller's own `username` (nullable)
  and `preferences`. One read for a profile/settings surface.
- `getCurrentUser()` on the api-client factory: `GET /api/v1/user/me`, validated
  against `GetCurrentUserResponse`.
- `modifyCurrentUser(body)` on the api-client factory: `PUT /api/v1/user/me` with
  a `UserModifyRequest` body (username and/or a partial preferences patch),
  returning `UserSchema`.

Purely additive. Requires the server `GET /api/v1/user/me` to populate the
`username` and `preferences` fields (proposit-server change lands in lockstep).
