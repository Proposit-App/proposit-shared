## Deviation from plan

`tcw capabilities add` and `tcw capabilities check` **cannot run from inside a
git worktree** in this workspace: tcw resolves `connected-projects` by relative
path, so from `.worktrees/<slug>/` it walks up to `.worktrees/tcw-config.yaml`
and fails with "registered target has no tcw-config.yaml".

Worked around by generating the entry with the CLI in the primary checkout,
moving the generated files into the worktree, and restoring the primary
checkout — so the format is still CLI-authored, not hand-written, and the work
still lands on the work branch. `tcw capabilities check` is run from the
primary checkout after the merge instead of inside the worktree.

Worth knowing for every other worktree-isolated item in this workspace: any
`tcw capabilities` / `tcw validate` call has to happen from the primary
checkout.
